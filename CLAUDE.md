# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MacHPSDR is a GTK4-based SDR (Software Defined Radio) control application for HPSDR hardware, written in C. It is a personal fork of [LinHPSDR](https://github.com/g0orx/linhpsdr) by John Melton (G0ORX/N6LYT), with a primary focus on macOS compatibility and several feature additions (freetune mode, waterfall themes, ppm correction, att10/att20 filter control, etc.). Licensed under the GNU GPL (v2 or later); see `LICENSE` and `NOTICE`.

The binary, install paths and config directory use the lowercase name `machpsdr`; the display name (window title, About dialog, `.app` bundle) is `MacHPSDR`.

## Build Commands

```bash
# Build the binary
make

# Install to /usr/local/bin
sudo make install        # Linux
make install             # macOS

# Clean build artifacts
make clean

# Build self-contained macOS .app bundle (requires dylibbundler)
make app
open MacHPSDR.app
```

No automated test suite exists — testing is manual with physical hardware. For
hardware-free smoke testing there is a synthetic **fake device**: run
`./machpsdr --faker <iq.wav>` (e.g. `--faker ft8.wav`) to loop an I/Q recording
through the full RX/decoder chain. With `--faker` the device-selection dialog is
skipped and the fake radio starts straight up, so it can be launched headless
(e.g. under lldb). See `fake_protocol.c` and the flag parsing in `main.c`.
The fake device advertises `supported_receivers = 2` and its feed loop drives
every allocated receiver, so it can also exercise the **diversity** UI (normally
Protocol-1-only): the VFO `DIV` button is shown for `PROTOCOL_FAKE` too, and the
feed loop feeds a diversity *hidden* receiver (`show_rx=FALSE`) so the mix
completes — otherwise the visible RX would freeze. The hidden RX is fed the
**same** I/Q as its visual partner (a small replay buffer in `fake_protocol.c`
stashes the visual channel's block and replays it for the hidden), so the two
diversity streams are coherent/identical rather than two independent file reads.
It is only for viewing/driving the UI (no real diversity gain).

**`create_receiver` hidden-RX invariant:** a receiver the caller asks to be
hidden (`show_rx=FALSE` — a diversity hidden RX or a PureSignal feedback RX) is
force-kept hidden after `receiver_restore_state`, because a stale persisted
`receiver[N].show_rx=1` (from a session where that slot was a normal shown RX)
would otherwise give it a full visual + update timer that `delete_receiver` does
not tear down — leaving the timer firing on freed widgets (`GTK_IS_WIDGET`
criticals / frozen UI) when diversity is switched off.

## Dependencies

### macOS (via Homebrew)
```bash
brew install fftw gtk4 gnome-icon-theme libsoundio libffi soapysdr dylibbundler
```

### Linux (via apt)
```bash
sudo apt-get install libfftw3-dev libpulse-dev libsoundio-dev libasound2-dev libgtk-4-dev libsoapysdr-dev
```

### WDSP (vendored — do NOT install upstream)
The patched WDSP this fork needs is vendored in-tree under `wdsp/` and is built
automatically by `make` on **both platforms** (`wdsp/libwdsp.dylib` on macOS,
`wdsp/libwdsp.so` on Linux); the binary finds it via rpath (`@loader_path/wdsp`
on macOS, `$ORIGIN/wdsp` on Linux). Do **not** `git clone g0orx/wdsp` and
`sudo make install` it — a stock system `-lwdsp` compiles but silently breaks
this fork's WFM demod and other DSP patches. The Makefile's `wdsp-local` target
(`$(MAKE) -C wdsp`) is an order-only prereq of the main binary on both platforms.

**Vendored under `wdsp/` too (NR3/NR4 advanced noise reduction):** `wdsp/rnnoise/`
(Xiph RNNoise, BSD-3 — model baked into `rnn_data.c`, own kiss_fft, no fftw) and
`wdsp/libspecbleach/` (LGPL-2.1+, spectral subtraction — needs **fftw3f/float
FFTW**, shipped by the same Homebrew `fftw` formula / Linux `libfftw3-dev`, no new
package). Both are unmodified upstream; their raw `.c` are compiled straight into
`libwdsp` via `NR_OBJS`/`NR_INCLUDES` in `wdsp/Makefile` (no meson/autotools — the
lib build systems are NOT used). See the NR3/NR4 note under `receiver.c/h`.

## Platform Differences

- **macOS**: Uses `audio.c` (SoundIO + CoreAudio) for audio, `mac_midi.c` for MIDI (CoreMIDI framework), no CWDAEMON support
- **Linux**: Uses `audio.c` with ALSA/PulseAudio/SoundIO, `alsa_midi.c` for MIDI, CWDAEMON enabled by default

> Note: `audio.c` is the audio backend on **both** platforms. The Makefile's `AUDIO_SOURCES=portaudio.c` (Darwin) is a dead variable — `portaudio.c` does not exist and is never compiled; `audio.c` is hardcoded in `SOURCES`/`OBJS`.

Platform is detected via `uname -s` in the Makefile (`Darwin` vs `Linux`).

## Source Layout

The ~90 first-party `.c/.h` live under `src/<subsystem>/`; the repo root holds
only the Makefile, `README`/`LICENSE`/`NOTICE`/`CLAUDE.md`, `mac-setup.sh` and
`machpsdr.desktop`. Program resources live in **`assets/`** (the PNG icons +
`cty.dat`) and screenshots/migration notes join the user manuals in **`doc/`**. The runtime lookups
that used to read `machpsdr.png` / `cty.dat` from the cwd now try `assets/`
first (see `main.c` icon path and `ft8_dxcc.c:open_cty`), and `make app` copies
them from `assets/`; the bare-cwd fallbacks are kept for older layouts.

| Dir | Contents |
|-----|----------|
| `src/core/` | app lifecycle + central state + fundamentals: `main`, `radio`, `receiver`, `transmitter`, `subrx`, `ext`, `error_handler`, `log`, `version`, `property`, `actions`, `vox`, `mode`, `filter`, `band`, `frequency`, `ringbuffer`, and the pure headers (`agc.h`, `adc.h`, `dac.h`, `alex.h`, `bandstack.h`, `channel.h`) |
| `src/proto/` | hardware comms + discovery: `protocol1/2`, `*_discovery`, `soapy_*`, `fake_protocol`, `discovery`, `discovered`, `reconnect`, `hl2`, `rigctl`, `puresignal`, `cwdaemon`, `dxcluster` |
| `src/dsp/` | `bpsk`, `diversity_mixer`, `peak_detect`, `ppm_cal` |
| `src/audio/` | `audio`, `recorder` |
| `src/midi/` | `midi2/3`, `midi_dialog`, `mac_midi`, `alsa_midi`, `midi.h` |
| `src/ui/` | all widgets/dialogs/spectrum: `*_dialog`, `*_panadapter`, `waterfall*`, `wideband*`, `vfo`, `meter`, `level_meter`, `tx_info*`, `radio_info`, `mic_*`, `drive_level`, `button_text`, `settings_ui`, `bookmark_dialog`, `cluster_dialog`, `css`, `gpu_image`, `waterfall_theme` |
| `src/decode/` | `ft8_*`, `sstv_*`, `wefax_*`, `cw_*` (decoders/encoders/panels) |

Vendored trees (`wdsp/`, `ft8_lib/`) are untouched at the repo root.

**Build mechanism:** the Makefile stays path-agnostic. `VPATH` (set to `$(SRCDIRS)`)
lets `make` resolve the bare `foo.c` names in `OBJS`/`SOURCES` from any subsystem
dir, and every dir is on the `-I` path (`SRC_INCLUDES`), so the flat
`#include "radio.h"` style keeps working with no per-file edits (all header
basenames are unique). Objects still build into the repo root as gitignored
`*.o`/`*.d`, so `OBJS` entries remain bare `foo.o` names. To add a new source,
drop it in the right `src/` dir and add its bare `foo.o` to `OBJS` (or the
relevant feature `*_OBJS`) as before — no path prefix.

## Architecture

### Application State
The global `RADIO *radio` struct (`radio.h`) is the central application state. It holds references to up to 8 `RECEIVER` structs, one `TRANSMITTER` struct, and hardware/protocol configuration.

### Key Modules

- **`main.c`** — Entry point, GTK init, device discovery, main window. Brought to the foreground on startup (`gtk_window_present` + a macOS `activateIgnoringOtherApps:YES` via the Obj-C runtime — AppKit is already in-process via GTK's quartz backend, no `.m`/framework link) so it doesn't open behind the terminal (matters under `--faker`). Sets the log level; calls `ft8_dxcc_init()` before `ft8_qso_init()`.
- **`radio.c/h`** — Radio lifecycle + hardware model definitions. Owns the bottom-bar Decode block + mode-gated selector, the FT8/SSTV/WEFAX panel sync helpers (`radio_{ft8,sstv,wefax}_panel_sync`, mutually exclusive over the second-RX slot), `radio_rebuild_rx_stack`, `radio_ppm_correction()`. Persisted in `radio_save_state`.
- **`receiver.c/h`** — Per-receiver state: VFO A/B, AGC, NR/NB/ANF, filters, modes, panadapter/waterfall.
  - **Advanced noise reduction (NR3/NR4):** the VFO **NR** button opens a menu OFF/NR/NR2/**NR3**/**NR4** (`vfo.c:nr_cb`/`nr_b_pressed_cb`). Four independent, mutually-exclusive `gboolean` flags on RECEIVER (`nr`=ANR, `nr2`=EMNR, `nr3`=RNNoise, `nr4`=libspecbleach); `receiver_nr_mode()`/`receiver_set_nr_mode()` are the single set/get helpers every UI/action/MIDI path routes through (rigctl keeps its own nr/nr2 CAT sets but now also clears nr3/nr4). `update_noise()` drives all four WDSP `Run` setters; persisted per-RX; the create/`SetAllRates` channel-init applies them; `subrx.c` mirrors them onto the sub-channel. **NR4 has 5 live-tunable params** (`nr4_reduction/smoothing/whitening/rescale/postfilter` on RECEIVER, persisted) — a **"Noise Reduction (NR4)" slider block in `receiver_dialog.c`** (Configure → RX-N) pushes each straight to WDSP (`SetRXASBNR*`) so the operator can dial the spectral denoiser in on real signals; `update_noise()` re-pushes them alongside the Run flags. **NR3 has no per-op params** (only the compile-time `RNNR_DEFAULT_SCALE`). **WDSP side (`wdsp/rnnr.c`+`sbnr.c`):** inserted between EMNR and bp1 bandpass at RXA position 0 (pre-AGC), gain-2.0-coupled via `RXAbp1Check`/`RXAbp1Set` (both got 2 new args). **NR3 buffering invariant:** RNNoise is fixed 480-sample frames but `ch.dsp_size` is 2048 (real HPSDR) or **5120 (faker/SoapySDR — `wide_buffers`)**; `rnnr.c` keeps its OWN per-instance ring buffers (NOT the reference port's file-static 2048 buffers — those are single-instance and fixed-size) and drains 480-frames dynamically, so any dsp_size and multiple RX are safe. `RNNR_DEFAULT_SCALE` (500000, matching the pihpsdr reference) pre-scales into RNNoise's int16-trained range (nets to unity). Faker-verified stable at 5120 (NR3 13 s under lldb, NR4 clean); **on-air audio quality unverified (no representative signal / hardware).**
  - **APF (CW audio peak filter) + variable squelch (parity 2.3):** `set_apf()` drives WDSP's `speak`/SPCW block (already in the RXA pipeline; `SetRXASPCW{Run,Freq,Bandwidth,Gain}` protos added header-only to `wdsp.h`). Peaks at the CW sidetone (`radio->cw_keyer_sidetone_frequency`, clamped ≥200 Hz per SPCW design 1); **runs only in CWL/CWU** so it can't ring on SSB/AM. Fields `apf_enable`/`apf_bw`/`apf_gain` on RECEIVER (persisted; UI = "Audio Peak Filter (CW)" frame in `receiver_dialog.c`, mirrors the NR4 block). **Variable squelch:** `set_squelch()` is now **mode-aware** — FM (FMN/WFM) → FMSQ (noise squelch, unchanged mapping), everything else → AMSQ amplitude/voice squelch (`thresh_db = -160..-40 dB` linear in the 0..1 SQL bar, on the pre-AGC signal magnitude). Exactly one WDSP squelch runs; the other is force-off, so a mode change can't strand a stale squelch on the wrong path. Bar at minimum = squelch OFF for every mode. `receiver_mode_changed` calls `set_squelch`+`set_apf` (replacing the old FMN-only force-disable). **`squelch` was previously not persisted at all — now saved** alongside the apf trio. Faker-verified (startup LSB→AMSQ path, no crash); **AMSQ dB scale and on-air APF benefit unverified (no representative signal/hardware)** — adjust `amsq_{min,max}_db` in `set_squelch` if the voice squelch mis-calibrates on air. **Deferred:** AMSQ max-tail UI, per-mode squelch memory, APF on subrx.
  - **Analyzer-feed heap-safety invariant:** WDSP's `Spectrum0()` writes each transfer block into a fixed I/Q input ring (`WDSP_ANALYZER_MAX_SIZE`×2 = 2¹⁹ complex samples) and only wraps at the ring end, so **the transfer block must divide the ring exactly** (see `// REQUIRES buff_size IS A SUB-MULTIPLE…` in `wdsp/analyzer.c`) or the last block before the wrap corrupts the heap. The wideband RX block (5120) and the widest TX block (40960) do **not** divide 2¹⁹, so the panadapter feed goes through `analyzer_feed()`, which splits any buffer into `ANALYZER_FEED_BLOCK` (1024 = gcd(5120,2¹⁹)) sub-blocks; `SetAnalyzer` is configured with `bf_sz == ANALYZER_FEED_BLOCK`. A `_Static_assert` in `receiver.h` enforces divisibility at compile time. (`bpsk.c` 2048 and `wideband.c` 16384 already use ring-dividing blocks.)
  - **Panadapter/waterfall vertical split (`vpaned`):** `restore_paned_position_cb` waits for a usably-tall pane (bounded retries) then clamps the split so both children keep their minimums. Panadapter can be turned off per RX (`rx->show_panadapter`, persisted): when hidden the waterfall takes full height, and `waterfall.c:resize_timeout` mirrors its width into `panadapter_width`/`pixels` and re-runs `receiver_init_analyzer()` so the feed keeps working (the panadapter normally drives the bin count via `rx->pixels = panadapter_width × zoom`).
  - **Per-mode filter & AGC memory:** `rx->mode_filter[MODES]` / `rx->mode_agc[MODES]` remember each mode's filter slot and AGC speed (so narrowing AM no longer narrows SSB). `receiver_mode_changed()` saves the outgoing mode's value and restores the incoming one; the filter/AGC change paths keep them in sync. Persisted; older configs re-sync `[mode_a]` from the legacy scalar on load. VFO AGC label follows via `vfo_update`.
  - **Tuning limits:** `receiver_move_a/b` clamp to `[0, receiver_max_frequency()]` — a hard **6 GHz** ceiling, lowered to `discovered->frequency_max` on narrower devices. **The guard is directional:** it rejects only moves pushing *further* outside the range, so a dial already above the device max (restored config, xvtr/VHF, VHF-centred recording) can still be tuned back down instead of freezing.
  - **Manual notch filter (MNF):** operator-placed notches on WDSP's notched-bandpass (`wdsp/nbp.c`), separate from auto-notch `anf`. `rx->notch[MAX_NOTCHES=16]` + `rx->notches`, stored **absolute RF Hz**, persisted; `receiver_notch_sync/add/delete/notch_at` are the ops (7 `RXANBP*` setters added to `wdsp.h`, header-only). **Invariant — absolute-RF anchoring:** WDSP's notch calc uses `offset = tunefreq + shift`, so `frequency_changed()` must call `RXANBPSetTuneFrequency(channel, frequency_a)` (alongside the existing `RXANBPSetShiftFrequency` ctun) in **both** the ctun/freetune *and* the plain-tuning branch — omit the plain branch and notches drift off-station under normal tuning. **UI:** Ctrl+click on the RX panadapter adds a 100 Hz notch / removes one under the cursor (Ctrl was free: plain=tune, Shift=TX offset, right=menu); drawn as a red band + centre line. Faker-verified (draw/persist/tune); on-air depth unverified. **Deferred:** TNF tracking, per-notch active toggle, width UI, settings-dialog list editor.
  - **Decoder tap:** `process_rx_buffer` feeds the decoder `radio->decode_mode` selects; raw off-air I/Q taps (recorder, PPM cal) are `full_rx_buffer`/`full_diviqrx_buffer`. When `decoder_taps_audio()`, `rx_panel_gain()` forces WDSP panel gain to unity (tap sees full level) and listen volume/mute is applied in software.
- **`transmitter.c/h`** — TX path: filtering, CTCSS, EER, PureSignal, metering. The TX panadapter feed uses `analyzer_feed()` for the same heap-safety reason (the 1920 kHz span's 40960-sample block doesn't divide 2¹⁹). `add_mic_sample()` substitutes the FT8/SSTV encoder output for the mic input while an encoder is active (universal across protocol1/2/soapy).
  - **TX audio processing chain (Configure → TX):** vendored-WDSP blocks wired to persisted `TRANSMITTER` fields + `transmitter_dialog.c` controls (applied in `create_transmitter`): **CESSB** (`SetTXAosctrlRun`), **CFC** 5-band Continuous Frequency Compressor (`SetTXACFCOMP*`), **Phase Rotator** (`SetTXAPHROT*`), a **10-band graphic EQ on TX *and* RX** (`Set{T,R}XAGrphEQ10`, `equalizer[11]`: 0=preamp, 1..10=32…16k Hz), and **per-stage LVL/CFC/COMP meters** (`GetTXAMeter`, drawn under ALC on the TX panadapter, each only while its stage is on + transmitting). The `SetTXACFCOMP*`/`SetTXAPHROT*`/`Set*GrphEQ10` prototypes were added to `wdsp.h` (header-only; symbols already exported). **Built + faker-smoke-tested only, unverified on air (no TX hardware).** Gotcha: this page overflowed the Configure window → every settings page is wrapped in a `GtkScrolledWindow` (`configure_dialog.c:add_page`, 1000×700 default).
- **`protocol1.c`, `protocol2.c`, `soapy_protocol.c`** — Hardware communication for Classic HPSDR, enhanced protocol, and SoapySDR devices. **PPM correction** (`radio->ppm_correction_value`, a **`double`**, ±500 ppm) is applied in the RX/TX tune-frequency computation of all three via `radio_ppm_correction(f_rf)` (`radio.c`; returns `llround(f_rf*ppm/1e6)`, `f_rf` = dial−LO). Protocol 1 reads it live in its output thread; Protocol 2 / SoapySDR pick up a change on the next `frequency_changed()` retune. Persisted as `%f` (older integer props load via `atof`).
  - **Protocol-2 feature gaps (deliberately deferred — no P2 hardware to verify, and the faker is `PROTOCOL_FAKE` not P2, so it can't exercise P2 code either):**
    - **PureSignal** — P2 path is a partial upstream port under `#ifdef PURESIGNAL_P2` (never defined; won't even build as-is, feedback DDC unrouted, TX atten a `//TODO`). Only the P1 `#ifdef PURESIGNAL` path is live. Finishing it blind (closed-loop predistortion) is high-risk + untestable without a P2 radio + feedback ADC.
    - **Diversity** — the mixer is already protocol-agnostic; only the `diversity_supported()` gate (`PROTOCOL_1`/`PROTOCOL_FAKE`) blocks P2. Wiring P2 = hidden RX `adc=1` + DDC-sync register in `receive_specific`, but needs a 2-coherent-ADC radio (ANAN-7000/8000) to verify. Write-only otherwise.
- **`ppm_cal.c/h`** — **PPM (oscillator) calibration against time-signal stations** (RWM/WWV/CHU/BPM on HF, MSF/DCF77/Droitwich on LF). `ppm_cal_tune_to_station()` parks the RX on the carrier in CW-USB for zero-beating by ear. **Automatic measurement:** carrier retuned to land at `PPM_MEAS_OFFSET` (1500 Hz, clear of DC); `ppm_cal_iq_feed()` (raw-I/Q tap in `receiver.c`) FFTs 32768-pt frames, parabolic-interpolates the carrier bin to ~0.1 Hz, averages SNR-gated frames. Closed loop: `ppm_new = ppm_old + (residual_Hz/(carrier−lo))·1e6`, `residual = measured − PPM_MEAS_OFFSET`; **sign follows the HPSDR non-inverted-I/Q convention (flip here if the loop diverges).** Runs on the RX audio thread (no-op when idle); UI polls `ppm_cal_measure_poll()`; RX VFO/mode/filter saved+restored (`ppm_cal_restore_rx()`). UI: **Configure → Misc** (`labels_dialog.c`); **Calibrate** doubles as **Stop**.
- **`dxcluster.c/h` + `cluster_dialog.c/h`** — **DX-cluster telnet client + spot overlay (P4.2).** A background `GThread` connects to a cluster, answers the login prompt (config `cluster_login` else `station_call`), parses `DX de <spotter>: <kHz> <call> <comment> <time>Z` lines into a mutex-guarded `DX_SPOT spots[256]` store (dup-merge within 500 Hz, 15-min age-out), and auto-reconnects (5 s). **Threading:** the socket thread never touches GTK — it only mutates the store; the fps panadapter timer already repaints the overlay, so no per-spot redraw is queued. **Connect is non-blocking** (`O_NONBLOCK` + `poll` capped at `DXCLUSTER_CONNECT_TIMEOUT_SEC`=10, checking `thread_running` every 100 ms) so `dxcluster_stop()` — called from the Configure toggle — can't freeze the UI on an unreachable host. **Config is snapshotted in `dxcluster_start()`** (`cfg_host/port/login`, thread stopped = no reader) so the socket thread never races the dialog rewriting live `RADIO` fields; edits apply on the next enable-toggle. **Overlay** (`rx_panadapter.c`, guarded by `cluster_enable && cluster_spots_show`): a tick + callsign per in-span spot, colour = HSV hue from the DXCC entity (`ft8_dxcc_entity`, grey if unknown). **Click-to-tune** lives in `receiver_released_cb` (NOT pressed — the release handler already tunes plain clicks, so tuning in pressed would double-tune): `dxcluster_nearest()` within ~6 px → `receiver_move(rx, delta, FALSE)` (exact, no step-snap, split-aware). Shared `receiver_x_to_freq()` is the one x→RF inverse used by both the notch and spot hit-tests. Persisted on `RADIO`. `MACHPSDR_CLUSTER_TESTSPOTS` injects 4 synthetic spots + force-enables the flags for faker verification. **Faker-verified (inject/connect/connect-timeout); on-air spot parsing + colouring unverified against a live busy cluster.**
- **`tci.c/h` + `tci_dialog.c/h`** — **TCI (Expert Electronics) server over WebSocket (P4.1). Phase A (control) + Phase B (IQ stream) done; Phase C (audio) deferred.** A background accept `GThread` + one detached `GThread` per client speak the TCI text protocol (`vfo:`/`modulation:`/`trx:` set-and-get, `;`-terminated) so loggers/skimmers can drive **and** follow VFO/mode/PTT — a modern alternative to CAT/rigctl, no VAC. **Transport is a real WebSocket** (RFC 6455): `ws_handshake()` computes `Sec-WebSocket-Accept` via **GLib** `g_checksum`(SHA1)+`g_base64_encode` (no vendored SHA1); `ws_recv_frame()` + `ws_write_header()`/`ws_send_blocking()` are a minimal text/**binary**/close/ping codec (7/16/64-bit lengths, no extensions). **Threading invariant (same as dxcluster):** socket threads never touch GTK — inbound commands dispatch to the GTK main thread via **`ext.c`** wrappers (`ext_set_frequency_a`/`ext_set_mode`/`ext_set_mox` + `g_idle_add`); getters read scalar `RADIO`/`RECEIVER` fields directly (benign race). **Outbound `tci_notify_{vfo,mode,trx}()`** are called from the GTK/audio thread at the choke points `frequency_changed()` (radio.c), `receiver_mode_changed()` (receiver.c) and `set_mox()` (radio.c); each early-returns on one atomic read when the server is off, else best-effort broadcasts. **`tci_stop()` is non-blocking** (shutdown+close the listen socket to unblock `accept`, shutdown every client fd, join only the accept thread — client threads self-clean). Mode map: internal↔TCI, both CWL/CWU→`cw` (TCI carries no sideband; incoming `cw`→CWU). SIGPIPE suppressed via `SO_NOSIGPIPE` (macOS) / `MSG_NOSIGNAL` (Linux). Persisted on `RADIO` (`tci_enable`/`tci_port`, default port 40001); UI = **Configure → TCI**. `MACHPSDR_TCI[=port]` force-enables for headless faker verification.
  - **Concurrency invariant (critical, added for Phase B):** three threads can now send to one socket — the client's own recv thread (control replies/handshake, **blocking**), the GTK thread (`tci_notify_*`) and the RX **audio** thread (IQ). Each client is a `TCI_CLIENT{fd, GMutex send_mtx, gint iq_on}` and **every send takes `send_mtx`**, so WebSocket frames never interleave mid-frame. Lock order is always `clients_mutex` → `send_mtx` (broadcasters hold both; the client thread holds only `send_mtx`) — no reverse path, no deadlock. Foreign-thread broadcasts use `g_mutex_trylock` + `MSG_DONTWAIT` so a slow/stalled client can **never** block the UI or audio thread (frame is dropped for that client); a rare partial write mid-frame desyncs that client's stream, so it is `shutdown()`-dropped rather than corrupted. `send_mtx` is static-storage GMutex (no init needed).
  - **Phase B — IQ stream out (`tci_iq_feed()`, tap in `receiver.c:full_rx_buffer` next to `scope_iq_feed`):** streams the **active RX**'s off-air I/Q (`rx->iq_input_buffer`, `gdouble`, pre-noise-blanker) as TCI binary frames to any client that sent `iq_start:0;` (stopped by `iq_stop:0;`). Frame = WS binary header + **64-byte TCI header** (`<8I32x` LE: rx=0, sample_rate=`rx->sample_rate`, data_format=**3** float32, codec=0, crc=0, **length = float count = 2×complex**, data_type=**0** IQ, channels=**2**) + interleaved float32 I/Q (doubles down-cast). - **`cw_decoder.c/h` + `cw_panel.c/h`** — **CW (Morse) audio→text decoder (P4.3).** Self-contained, no WDSP/FFT. Tapped in `process_rx_buffer` on the 48 kHz demod audio in **CWL/CWU** when `decode_mode==DECODE_CW`. Pipeline: a **Goertzel bank** (16 bins, 400–1000 Hz, 128-sample blocks) tracks the keyed tone (dominant slow-EMA bin, auto-follows the operator's pitch — no manual pitch set) → **envelope modulation-depth squelch** → **adaptive envelope + Schmitt trigger** → mark/space run classification against an **adaptive dot length** (EMA toward a rolling-minimum mark) → **Morse table** → text. **Noise squelch (critical — a CW decoder must stay silent on band noise/QRM, not stream garbage):** the bank is deliberately oversampled (40 Hz bins over ~375 Hz per-filter resolution) so it *can't* resolve spectral tonality — a single tone lights up every bin. The tell between CW and noise is **temporal**: total in-band energy (sum of all bins) swings between mark and gap on real keying but is statistically near-constant on broadband noise. So a fast-attack/slow-decay peak follower `sig_hi` over that energy vs the slow `floor_env` gives the keying **modulation depth**; the Schmitt trigger + emit only run while `sig_hi/floor ≥ SQ_OPEN` (10, hysteresis `SQ_CLOSE` 3). While squelched, no marks form and nothing is emitted. *(Earlier spectral peak/median tonality gates were tried and fail — the oversampled window makes tone and noise tonality overlap.)* **Second gate — Morse-timing plausibility:** a strong NON-CW signal (SSB carrier, DC birdie, AGC-pumped noise) can modulate enough to open the squelch, so emission is *also* gated on `timing_ok()`: each mark's distance to the nearest of {1,3} dot-units and each gap's to {1,3,7} is EMA'd (`timing_err`), and characters are emitted only while that error stays under `TIMING_TOL` (0.55). Real CW → tiny error → decodes (loses ~1 char during lock-in, `timing_err` starts pessimistic); chaotic non-CW timing → error high → suppressed. **`TIMING_TOL` is 1.6 (loose): real off-air CW jitters (err ~0.6–1.5), so a tight gate suppressed genuine copy — the squelch is the primary noise defence.** **Dot-length estimate is an EMA average of dot-marks (dashes nudge it via dash/3), NOT a rolling minimum** — the old rolling-min collapsed `dot_ms` to its floor on real CW (natural dot spread + short key-click glitches dragged the minimum down until every dot read as a dash), which is why it decoded almost nothing on air until fixed. Marks < `MIN_MARK_MS` (18 ms) are rejected as glitches. **Verified on a real off-air CW AF recording (decodes correctly); test the decoder headlessly by feeding a `rec_*_af.wav` to a small harness that calls `cw_decoder_add_audio` — do NOT open the app just to test.** `wpm=1200/dot_ms` clamped 5–60. **Threading:** decoder runs on the RX audio thread; a `GMutex` guards the pending-text ring **and** the published status trio (`pub_dot_ms/tone/elements`) — the panel poll (`g_timeout_add` 200 ms) drains text + reads status under the same lock (never a torn double). `decoder_taps_audio()` includes CW → unity WDSP panel gain (decodes while muted). **UI — the bottom Decode block is the primary readout:** `rds_update_cb` shows a WPM/tone line + a rolling tail of the decoded text via `cw_decoder_get_recent()` (a **non-draining** peek of a separate history ring, so it doesn't steal chars from the panel's `get_text()` drain); the readout label flips to `PANGO_ELLIPSIZE_START` for CW so the newest copy stays visible. The embedded panel (`cw_panel_create()`, a scrolling monospace `GtkTextView` + Clear) is **optional** (Show CW) and just adds full scrollback. `radio_cw_panel_sync()` gates on `cw_panel_open && mode∈{CWL,CWU} && decode_mode==DECODE_CW`, mutually exclusive with FT8/SSTV/WEFAX (shared RX2 slot; `panels_idle()` is the single source of truth gating Add Receiver). `receiver_mode_changed` calls **all four** panel syncs so leaving the mode tears the panel down. `MACHPSDR_CW_ECHO` echoes decoded chars to stderr for headless verification. Folded under the **`SSTV`** build flag (like WEFAX). **Verified:** decoder unit-tested (synthetic Morse → exact text); **decodes a real off-air CW recording correctly** (user-confirmed); squelch keeps it silent on the fake device's noise (was streaming garbage before the modulation-depth squelch — the user's original bug report). Gotcha: setting `decode_mode` via props does NOT fire `decode_sel_changed` → unity gain isn't applied that way; only real UI selection is faithful (so headless faker tests underfeed the decoder — test the decoder on `rec_*_af.wav` instead).
- **`cw_encoder.c/h`** — **CW (Morse) TX engine / text sender (P4.4a).** Inverse of the decoder: ASCII→Morse→keyed sidetone audio at 48 kHz. `cw_encode_to_audio()` is a **pure** function (own char→code table, PARIS timing `dot_ms=1200/wpm`, dot=1/dash=3/gaps=1/3/7 dot-units, `weight` scales the mark and compensates the following gap, raised-cosine ~5 ms edge ramp, phase-continuous sine) — **no RADIO/GTK/MOX deps, so it links into a headless round-trip harness** (`cw_encode_to_audio → cw_decoder_add_audio`, verified exact on CQ/callsign/digit messages at WPM 15–30). Live side mirrors `ft8_encoder.c`/`sstv_encoder.c`: `cw_tx_send_text()` expands macros (`%C`→`station_call`, `%%`→`%`), encodes into a **fixed static `wave[]` buffer (never freed — no use-after-free)**, publishes it with a `g_atomic` release on `active` (acquire in `cw_tx_next_sample`, lock-free audio-thread read — needed on Apple-Silicon weak ordering), keys MOX (if not already keyed), and a 100 ms `tx_tick` watchdog drops MOX on completion **or** a stall (fires regardless of `we_keyed`, so a stalled feed can't wedge `active`). Gated on `radio->can_transmit` + **`transmitter_get_mode()==CWL/CWU`** (same mode `add_mic_sample` substitutes on — not `active_receiver->mode_a`) + not `radio->tune`. **Hooked into `add_mic_sample`** (`transmitter.c`): the CWL/CWU branch (checked **before** `radio->tune`) substitutes `cw_tx_next_sample()` when `cw_tx_active()`, else 0.0. **Message memories:** `radio->cw_memory[CW_N_MEMORIES=8][CW_MSG_LEN=64]`, persisted (`radio.cw_memory[%d]`), defaults seeded **only when no `cw_memory` key exists at all** (so cleared memories stay cleared); edited in the dedicated **Configure → CW** tab (`cw_dialog.c` — the CW keyer/sidetone/memory settings live on their own Configure page, split out of the Radio page), sent from the CW panel's TX row (M1..M8 + free-text + Send/Stop + live WPM spin). Folded under **`SSTV`** flag. **Verified:** clean build + headless encoder↔decoder round-trip; **on-air RF path UNVERIFIED (no TX hardware)** — like the whole TX family. Phase B (`cw_keyer.c`) adds a real-time **KEYER** tone mode to this same module (`cw_tx_key()` gates a live sidetone; `tx_mode` ∈ IDLE/MESSAGE/KEYER picks what `cw_tx_next_sample()` renders; MOX owned here with a break-in hang floored at ~2 dot-units + a stall watchdog). `cw_tx_key`'s down-edge is safety-gated on `can_transmit` + `transmitter!=NULL` + `transmitter_get_mode()∈{CWL,CWU}` (covers both paddle callers).
- **`cw_keyer.c/h`** — **software iambic CW keyer (P4.4b).** Canonical **Curtis A/B** paddle state machine driving `cw_tx_key()`. `cw_keyer_paddle(DOT/DASH, pressed)` is called from **keyboard** (`[`/`]` in `receiver.c` key-pressed/released, gated to CWL/CWU on press, release always fires) and **MIDI** (`CWLEFT`/`CWRIGHT` with `ONOFF`, `midi3.c` — wired only `#if !CWDAEMON`, since a CWDAEMON build's `DoTheMidi` claims `CWRIGHT` as a hardware straight-key first). Honours `cw_keyer_mode` (Straight/A/B), `cw_keyer_speed`, `cw_keyer_weight`, `cw_keys_reversed`. Timing: `g_timeout_add(2ms)` tick calls `cw_keyer_advance(read_time_now())`, scheduled from the element boundary (no drift); the timer **self-removes at idle** (no permanent tick). **Invariants (all from a /code-review pass — a keyer that strands the TX keyed is the cardinal sin):** paddle state stored as **physical** contacts, reversal applied at read time (`dot_down()`/`dash_down()`) so toggling `cw_keys_reversed` mid-hold can't strand a flag; switching to Straight mid-element cleans up + releases the key; a **stuck-paddle timeout** (`CW_KEYER_STUCK_S`=15) force-releases a held paddle with no state change (lost key-up on focus loss / dropped MIDI note-off). **Test seam:** `cw_keyer_set_test_hook()` + `cw_keyer_advance(now_s)` let a **headless unit test** drive synthetic paddle timelines on a mock clock and assert the element sequence — **verified:** dit/dah taps, hold→repeat, squeeze→strict alternation, **Mode B = exactly one more trailing element than Mode A**, `cw_keys_reversed` swap, straight-key passthrough, plus exact dit(2u)/dah(4u) periods and reverse-toggle-mid-hold. **On-air / real-paddle UNVERIFIED (no TX hardware, no physical paddle)** — the unit test is the proof. Folded under **`SSTV`** flag.
- **`subrx.c`** — Sub-receiver: a second WDSP demod channel (`rx->channel + SUBRX_BASE_CHANNEL`) on the same off-air I/Q, own VFO-B freq/mode/filter/AGC, toggled by **SUBRX** (`vfo.c`). Audio: main left / sub right with an adjustable crossfeed `rx->subrx_mix` (0=split…100=mono). Both persisted. **Gotcha:** since `frequency_changed()`/`process_rx_buffer()` deref `rx->subrx` whenever `subrx_enable` is set, a restored "on" state is parked in `rx->subrx_restore_pending` and only applied at the **end** of `create_receiver` (after the main channel opens) — applying it earlier NULL-derefs the not-yet-created sub-channel.
- **`diversity_mixer.c` / `diversity_dialog.c`** — Diversity reception (combine two coherent ADC streams). UI on the always-present **Configure → Diversity** page: an **Enable** checkbox `add_receiver(FALSE)`s a hidden RX + `add_diversity_mixer()` (WDSP `create_divEXT`); mixing in `add_iq_samples`. Greyed unless `diversity_supported()` (**Protocol 1 or fake AND `supported_receivers ≥ 2`**); gain/phase/ADC controls act on `page_dmix()` (active RX's mixer). **Protocol 1 only, unverified on hardware.** **Invariant:** the mixer's `iq_buffer_size` must equal the RX buffer size (not a hardcoded 1024); the fake device feeds/replays the hidden RX in `fake_protocol.c`.
- **`recorder.c/h`** — **I/Q + demodulated-audio recorder** (global singleton, own `GMutex`). Streams two 16-bit stereo WAVs: `rec_<UTC>_iq.wav` (off-air I/Q tapped in `full_rx_buffer` **before** the noise blanker — same format `--faker` reads, so loop-back-able) and `rec_<UTC>_af.wav` (48 kHz demod audio before software volume). Streaming RIFF writer, header patched on stop. Taps run on the RX audio thread; `recorder_toggle` starts/stops from the SETUP Record button. Settings in Configure → Recording. *(Known limit: 32-bit WAV size fields overflow past ~44 min @384k; data still written.)*
- **`ext.c`** — Thread-safe UI dispatch helpers (`ext_*` functions wrap `g_idle_add()`).
- **`log.c/h`** — **Levelled console logging.** Three levels `ERROR < INFO < DEBUG`; macros `log_error()`/`log_info()`/`log_debug()` write to **stderr**, mutex-serialised (safe from any thread) and level-prefixed. The level guard lives in the macro (a single int compare against `machpsdr_log_level`), so a `log_debug()` on a hot path costs nothing and its args aren't evaluated when DEBUG is off. Threshold defaults to **INFO**, set at start-up in `main.c` from `MACHPSDR_LOG=error|info|debug` then overridden by the CLI (`--log-level <lvl>`, `--debug`/`-v`/`--verbose`, `--quiet`/`-q`). **New code should use the `log_*` macros, not bare `printf`/`g_print`** (the vendored `ft8_lib/` and `wdsp/` trees are left untouched).

### UI Dialogs
All dialogs follow the `*_dialog.c/h` naming convention: `radio_dialog`, `receiver_dialog`, `transmitter_dialog`, `midi_dialog`, `configure_dialog`, `bookmark_dialog`, `diversity_dialog`, `pa_dialog`, `eer_dialog`, `puresignal_dialog`, etc.

### Threading
Background tasks (protocol I/O, wisdom file creation) use `GThread`. UI updates must be dispatched to the GTK main thread via `g_idle_add()` or the `ext_*` wrappers in `ext.c` — never call GTK functions directly from protocol/audio threads.
