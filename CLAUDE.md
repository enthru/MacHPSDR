# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MacHPSDR is a GTK4-based SDR (Software Defined Radio) control application for HPSDR hardware, written in C. It is a personal fork of [LinHPSDR](https://github.com/g0orx/linhpsdr) by John Melton (G0ORX/N6LYT), with a primary focus on macOS compatibility and several feature additions (freetune mode, waterfall themes, ppm correction, att10/att20 filter control, etc.). Licensed under the GNU GPL (v2 or later); see `LICENSE` and `NOTICE`.

The binary, install paths and config directory use the lowercase name `machpsdr`; the display name (window title, About dialog, `.app` bundle) is `MacHPSDR`.

## Build Commands

```bash
# Build the binary
make

# Install to /usr/local/bin
sudo make install        # Linux
make install             # macOS

# Clean build artifacts
make clean

# Build self-contained macOS .app bundle (requires dylibbundler)
make app
open MacHPSDR.app
```

No automated test suite exists — testing is manual with physical hardware. For
hardware-free smoke testing there is a synthetic **fake device**: run
`./machpsdr --faker <iq.wav>` (e.g. `--faker ft8.wav`) to loop an I/Q recording
through the full RX/decoder chain. With `--faker` the device-selection dialog is
skipped and the fake radio starts straight up, so it can be launched headless
(e.g. under lldb). See `fake_protocol.c` and the flag parsing in `main.c`.

## Dependencies

### macOS (via Homebrew)
```bash
brew install fftw gtk4 gnome-icon-theme libsoundio libffi soapysdr dylibbundler
```

### Linux (via apt)
```bash
sudo apt-get install libfftw3-dev libpulse-dev libsoundio-dev libasound2-dev libgtk-4-dev libsoapysdr-dev
```

### WDSP (vendored — do NOT install upstream)
The patched WDSP this fork needs is vendored in-tree under `wdsp/` and is built
automatically by `make` on **both platforms** (`wdsp/libwdsp.dylib` on macOS,
`wdsp/libwdsp.so` on Linux); the binary finds it via rpath (`@loader_path/wdsp`
on macOS, `$ORIGIN/wdsp` on Linux). Do **not** `git clone g0orx/wdsp` and
`sudo make install` it — a stock system `-lwdsp` compiles but silently breaks
this fork's WFM demod and other DSP patches. The Makefile's `wdsp-local` target
(`$(MAKE) -C wdsp`) is an order-only prereq of the main binary on both platforms.

## Platform Differences

- **macOS**: Uses `audio.c` (SoundIO + CoreAudio) for audio, `mac_midi.c` for MIDI (CoreMIDI framework), no CWDAEMON support
- **Linux**: Uses `audio.c` with ALSA/PulseAudio/SoundIO, `alsa_midi.c` for MIDI, CWDAEMON enabled by default

> Note: `audio.c` is the audio backend on **both** platforms. The Makefile's `AUDIO_SOURCES=portaudio.c` (Darwin) is a dead variable — `portaudio.c` does not exist and is never compiled; `audio.c` is hardcoded in `SOURCES`/`OBJS`.

Platform is detected via `uname -s` in the Makefile (`Darwin` vs `Linux`).

## Build Feature Flags (Makefile)

| Flag | Default | Notes |
|------|---------|-------|
| `SOAPYSDR` | enabled | RTL-SDR/LimeSDR/HackRF support (RX; HackRF TX implemented, half-duplex, untested on hardware) |
| `MIDI` | enabled | MIDI controller support |
| `CWDAEMON` | enabled (Linux only) | CW keying via unixcw |
| `PURESIGNAL` | disabled | Adaptive distortion correction (Protocol 1 only) |
| `OPENGL` | disabled | OpenGL rendering |
| `FT8` | enabled | FT8 RX decoder + TX/auto-QSO (decoder auto-enabled in DIGU; big QSO panel is opt-in via a bottom-bar toggle); vendored `ft8_lib/` |
| `SSTV` | enabled | SSTV image RX decoder **and TX encoder** (Martin/Scottie/Robot/PD, incl. ISS Robot 36 & PD120) + embedded image panel; **also gates the WEFAX / HF-radiofax RX decoder** (`wefax_decoder.c`/`wefax_panel.c`); self-contained (no external DSP) |

To toggle, comment/uncomment the `*_INCLUDE=*` lines near the top of the Makefile.

## Architecture

### Application State
The global `RADIO *radio` struct (`radio.h`) is the central application state. It holds references to up to 8 `RECEIVER` structs, one `TRANSMITTER` struct, and hardware/protocol configuration.

### Key Modules

- **`main.c`** — Entry point, GTK init, device discovery, main window creation. **Window is brought to the foreground on startup** (`gtk_window_present` + a macOS-only `[[NSApplication sharedApplication] activateIgnoringOtherApps:YES]` sent via the Obj-C runtime — AppKit is already in-process via GTK's quartz backend, so no framework link / `.m` file is needed), so it doesn't open hidden behind the launching terminal. Matters most under `--faker`, where the device-selection dialog that would otherwise grab focus is skipped.
- **`radio.c/h`** — Radio lifecycle management, hardware model definitions (ANAN, Hermes, Hermes-Lite, Orion, Atlas, etc.)
- **`receiver.c/h`** — Per-receiver state: VFO A/B, AGC, NR/NB/ANF, filters, modes, panadapter/waterfall. **Analyzer-feed heap-safety invariant:** WDSP's `Spectrum0()` writes each transfer block into a fixed I/Q input ring (`XCreateAnalyzer` `max_size` × `dSAMP_BUFF_MULT`(2) = `WDSP_ANALYZER_MAX_SIZE`×2 = 2¹⁹ complex samples) and only wraps its write index at the ring end, so **the transfer block must divide the ring exactly** (`// REQUIRES buff_size IS A SUB-MULTIPLE…` in `wdsp/analyzer.c`) — otherwise the last block before the wrap runs off the buffer and corrupts the heap (intermittent, ASLR-dependent crash ≈ every ring cycle). The wideband RX block (5120 = 2¹⁰·5) and the widest TX block (40960 at the 1920 kHz span) do **not** divide 2¹⁹, so the panadapter feed goes through `analyzer_feed()` (`receiver.c`), which splits any buffer into `ANALYZER_FEED_BLOCK` (1024 = gcd(5120,2¹⁹)) sub-blocks; `SetAnalyzer` is configured with `bf_sz == ANALYZER_FEED_BLOCK` to match. A `_Static_assert` in `receiver.h` enforces the divisibility at compile time. `bpsk.c` (2048) and `wideband.c` (16384) already use ring-dividing blocks and are unaffected. **Panadapter/waterfall vertical split (`vpaned`):** the spectroscope (panadapter) is the top child, waterfall the bottom. The panadapter has a **minimum height** (`MIN_PANADAPTER_HEIGHT` 90) with `shrink_start_child=FALSE` so the pane can never open it as a sliver, and `restore_paned_position_cb` waits for a usably-tall pane (bounded retries via `paned_restore_tries`) then clamps the restored split so both children keep their minimums — the fix for the GTK4 "spectroscope opens collapsed" bug. The panadapter can also be **turned off entirely** per receiver (`rx->show_panadapter`, a check box in the receiver settings dialog, persisted): `receiver_apply_panadapter_visibility()` sets the panadapter widget invisible so the `GtkPaned` gives the waterfall the whole height. Because the panadapter normally drives the analyzer bin count (`rx->pixels = panadapter_width × zoom` in `rx_panadapter.c:resize_timeout`), when it is hidden the **waterfall takes over** — `waterfall.c:resize_timeout` mirrors its own width into `panadapter_width`/`pixels` and re-runs `receiver_init_analyzer()`, so the spectrum feed keeps working with no panadapter. **Per-mode filter memory:** every mode has its own filter *table* (`filters[mode]` in `filter.c`), but the *selected* slot used to be a single shared `rx->filter_a`, so choosing a bandwidth in one mode changed which slot every other mode used (e.g. narrowing AM also narrowed SSB). `rx->mode_filter[MODES]` now remembers each mode's selected slot: `receiver_mode_changed()` saves the outgoing mode's `filter_a` into it and restores the incoming mode's, `receiver_filter_changed()` keeps `mode_filter[mode_a]` in sync with `filter_a`, and the array is persisted per receiver (`mode_filter[i]` props; a restore fallback re-syncs `mode_filter[mode_a]=filter_a` for older configs that lack it). `mode.h` gained an include guard because `receiver.h` now includes it for `MODES`.
- **`transmitter.c/h`** — TX path: filtering, CTCSS, EER, PureSignal, metering. The TX panadapter feed uses `analyzer_feed()` (see `receiver.c/h`) for the same input-ring heap-safety reason — the 1920 kHz span's 40960-sample output block does not divide WDSP's 2¹⁹ analyzer ring.
- **`protocol1.c`, `protocol2.c`, `soapy_protocol.c`** — Hardware communication for Classic HPSDR, enhanced protocol, and SoapySDR devices respectively. **PPM correction** (`radio->ppm_correction_value`, a **`double`**, ±500 ppm — fractional for sub-ppm resolution, which matters on the high bands) is applied in the RX/TX tune-frequency computation of **all three** protocols via the shared `radio_ppm_correction(f_rf)` helper (`radio.c`; returns `llround(f_rf*ppm/1e6)`, full floating precision, `f_rf` = dial−LO). Protocol 1 reads it live in its output thread; Protocol 2 / SoapySDR pick up a changed ppm on the next `frequency_changed()` retune. (Persisted as `%f`; older integer-valued props load fine via `atof`.)
- **`ppm_cal.c/h`** — **PPM (oscillator) calibration against time-signal stations.** Holds the reference-station table (`PPM_STATION` name+carrier Hz — RWM/WWV/CHU/BPM on HF, MSF/DCF77/Droitwich on LF) with `ppm_station_count()`/`ppm_station(i)` accessors, and `ppm_cal_tune_to_station()` (parks the active RX on the carrier in CW-USB for zero-beating by ear). Selected station persisted in `radio->ppm_ref_station`. **Automatic measurement:** `ppm_cal_measure_start()` retunes the active RX so the carrier lands at a fixed audio offset (`PPM_MEAS_OFFSET` 1500 Hz, clear of the DC spike), then `ppm_cal_iq_feed()` — a tap in `receiver.c:full_rx_buffer`/`full_diviqrx_buffer` on the **raw off-air I/Q** (demod-independent) — accumulates `PPM_FFT_N`(32768)-pt frames, runs a **self-contained radix-2 FFT** (no FT8/kiss/fftw dependency), finds the carrier bin, parabolic-interpolates to sub-bin (~0.1 Hz), and averages `PPM_FRAMES`(6) frames against ionospheric Doppler (skipping `PPM_SETTLE` after retune, SNR-gated). Closed-loop correction `ppm_new = ppm_old + (residual_Hz/(carrier−lo))·1e6` where `residual = measured − PPM_MEAS_OFFSET`; sign follows the HPSDR non-inverted I/Q convention (`iq[2k]=I`, `[2k+1]=Q`, above-LO ⇒ +baseband) — re-running shows the residual collapse toward 0. Runs on the RX audio thread (atomic fast-path no-op when idle); the UI polls `ppm_cal_measure_poll()`. The RX's VFO frequency/mode/filter are saved at start and restored by `ppm_cal_restore_rx()` when the run ends (so the radio is not left parked on the reference station). UI in the **Configure → Misc** page (`labels_dialog.c`, "Frequency Calibration (PPM)" frame): ppm spinner (0.01 steps) + station combo + **Calibrate** & **Tune** buttons + status/result readouts. The **Calibrate** button doubles as **Stop** while running (`ppm_cal_measure_cancel()`); the ~150 ms GTK poll shows per-frame progress (`N/6`), auto-applies the result to the spinner on success, restores the RX, and is torn down on the page's `destroy`.
- **`discovery.c`, `protocol1_discovery.c`, `protocol2_discovery.c`, `soapy_discovery.c`** — Network device discovery
- **`vfo.c`** — Frequency display and VFO control widget
- **`meter.c`** — Analog S-meter widget (`update_meter`). The needle angle is driven by a **smoothed** value with mechanical-meter ballistics rather than the raw `rx->meter_db`: a per-frame exponential ease toward the target with **fast attack / slower decay** (rising signals catch up quickly, peaks linger then settle). Strength is the per-receiver **`rx->meter_smoothing`** setting (0 = off/instant … 100 = max, default 50; a slider in the receiver settings dialog's Panadapter frame, persisted). The smoothing scales the decay time constant (0…0.5 s) with attack = decay/5; coefficients are derived from time constants and `rx->fps` so the feel is frame-rate independent. The needle state (`meter_needle_db`/`meter_needle_init`) is seeded on first draw (no sweep from zero) and reseeded when the slider changes. The numeric dBm readout keeps showing the raw instantaneous value.
- **`waterfall.c`, `rx_panadapter.c`, `tx_panadapter.c`** — Spectrum display rendering
- **`audio.c`** — Audio I/O (SoundIO on both platforms; ALSA/PulseAudio on Linux, CoreAudio on macOS). Includes the synthetic "System Default" output device (`AUDIO_SYSTEM_DEFAULT_NAME`), which new receivers use by default
- **`midi2.c`, `midi3.c`** — MIDI learn and control mapping (platform-agnostic); `mac_midi.c` / `alsa_midi.c` for platform I/O
- **`actions.c`** — Global action dispatch (used for keybindings and MIDI mappings)
- **`property.c`** — Persistence: save/load radio configuration to/from properties files (`~/.local/share/machpsdr/<device-mac>.props`; MIDI mappings in `midi.props`)
- **`waterfall_theme.c`** — Waterfall color theme definitions
- **`gpu_image.c/h`** — **`GpuImage`, a reusable GTK4 GPU-composited image widget.** Subclasses `GtkWidget` and overrides `snapshot()` to draw a `GdkPixbuf` as a `GdkMemoryTexture` through the render-node pipeline (GPU), replacing the deprecated cairo `gdk_cairo_set_source_pixbuf()` blit. Backs **all** raster surfaces: the RX/wideband/FT8 waterfalls (`waterfall.c`, `wideband_waterfall.c`, `ft8_waterfall.c`) and the SSTV/WEFAX image panels (`sstv_panel.c`, `wefax_panel.c`). Keeps the old "draw reads the live pixbuf" flow via a **pull** `GpuImageSource` callback (so existing `gtk_widget_queue_draw()` sites are unchanged); a per-widget **fit mode** (`GPU_FIT_STRETCH`/`LETTERBOX`/`WIDTH_BOTTOM`) + `GskScalingFilter` (`gtk_snapshot_append_scaled_texture`); an optional **`GpuImageOverlay`** that reuses the existing cairo overlay code (passband/cursor, grid/TX-marker) via the non-deprecated `gtk_snapshot_append_cairo()`; and a **`"resize"`** signal (emitted from `size_allocate`) that re-implements GtkDrawingArea's so the pixbuf-reallocating resize callbacks need no edits. The texture is built from a **copy** of the pixbuf bytes (`g_bytes_new` → `gdk_memory_texture_new`) because a `GdkMemoryTexture`'s backing memory must stay immutable, whereas the waterfall pixbufs are mutated in place each frame. Note: `gdk_texture_new_for_pixbuf()` is itself deprecated (GTK 4.20), hence the direct memory-texture path. This retired the last deprecation, so `-Wno-deprecated-declarations` is no longer in the Makefile CFLAGS.
- **`hl2.c`** — Hermes-Lite 2 specific protocol extensions
- **`wideband.c`, `wideband_panadapter.c`, `wideband_waterfall.c`** — Wideband spectrum display (separate from per-receiver panadapter)
- **`ft8_decoder.c/h`** — FT8 receive decoder. **Decoder selection:** no decoder runs by default; the operator picks one from the bottom-bar Decode block (`radio->decode_mode`, a `decode_mode_t` — `DECODE_OFF`/`FT8`/`FT4`/`SSTV`/`WEFAX` — the single source of truth for *which* decoder taps the active RX's audio, persisted). The tap in `receiver.c:process_rx_buffer` feeds the FT8 decoder while the active RX is in a **digital mode (DIGU *or* DIGL)** *and* `decode_mode` is `DECODE_FT8`/`DECODE_FT4` (the selector also keeps `radio->ft8_proto` in sync — 0/1 — for the TX/QSO/reporter path). `DECODE_SSTV` routes to the separate `sstv_decoder.c`, and `DECODE_WEFAX` to `wefax_decoder.c` (both below), not this module. It decimates the 48 kHz demod audio to 12 kHz, buffers 15-second UTC slots, decodes in a background `GThread`. Displayed in the bottom-bar decoder block (see `rds_update_cb` in `radio.c`). Uses the vendored `ft8_lib/` (Karlis Goba, MIT); gated by the `FT8` Makefile flag. **Decodes independently of the listening volume/mute:** when a decoder is tapping the RX (see `decoder_taps_audio()` in `receiver.c`) the WDSP audio-panel gain is forced to unity (`rx_panel_gain()`) so the decoder tap (`rx->audio_output_buffer`) always gets a full-level signal, and the volume/mute is applied to the audible output in software in `process_rx_buffer()` — the operator does not listen to FT8. (With no decoder selected, DIGU/DIGL behave as normal listening modes — no unity-gain override.) Each `FT8_DECODE` also carries structured `call_to`/`call_de`/`extra` fields (via `ftx_message_decode_std`) for the QSO engine. **FT4 support:** the decoder is protocol-aware via `ft8_decoder_set_protocol(ft4)` (called each RX buffer from `receiver.c`, derived from `decode_mode`; `radio->ft8_proto` remains the source of truth read by the encoder/QSO/reporters — 0=FT8, 1=FT4). In FT4 the decode window (`slot_samples()`), decode cadence (`decode_hop()`) and minimum-audio guard (`mon_min_samples()`) are the shorter 7.5 s-slot values, the `monitor_config_t` protocol is `FTX_PROTOCOL_FT4`, and `measure_snr()` is **protocol-parametric** (n_sym / n_tones / symbol_period) so FT4 gets a real 4-GFSK WSJT-X-style SNR (reference term `10log10(2500/tone_hz)` = 20.79 dB for FT4's 20.833 Hz tone spacing, vs 26.02 dB for FT8) — AWGN-calibrated to ~±1 dB. The slot-boundary label (`work_slot_time`) is computed in ms and **rounded** to the nearest second so FT4's half-second (7.5 s) boundaries map back to the correct slot index in `slot_even_from_utc()`. `SLOT_SAMPLES`/`RING_CAP` stay sized for the longer FT8 window (FT4 fits inside).
- **`ft8_encoder.c/h`** — FT8/FT4 **TX engine** (Phase 2). `ft8_tx_prepare()` packs a message (`ftx_message_encode`) and synthesizes the GFSK waveform at the 48 kHz mic rate (ported `gfsk_pulse`/`synth_gfsk`). Protocol-selected by `radio->ft8_proto`: **FT8** = `ft8_encode`, BT=2.0, 79 symbols ≈ 12.64 s (7680 samp/sym); **FT4** = `ft4_encode`, BT=1.0, 105 symbols ≈ 5.04 s (2304 samp/sym) — `synth_gfsk` is parametric (`nsps`, `bt`, `n_sym`), the shared `wave[]` buffer is sized to the longer FT8 waveform. A ~100 ms slot scheduler (`ft8_tx_arm`, GTK thread) keys MOX (`set_mox`) early in the chosen even/odd UTC slot and drops it when the waveform ends. Timing is done in **wall-clock milliseconds** (`g_get_real_time`) with a protocol slot length `TX_SLOT_MS()` (15000/7500) so FT4's half-second boundaries are honoured. `add_mic_sample()` in `transmitter.c` substitutes `ft8_tx_next_sample()` for the mic input in DIGU while `ft8_tx_active()`, so the normal DIGU (USB) TX chain modulates the tone to dial+offset (universal across protocol1/2/soapy). **MOX safety watchdog:** `tx_tick` stamps `key_time_ms` when it raises MOX and force-drops it if MOX has been held longer than the actual waveform length + `FT8_TX_MAX_MARGIN_MS` (2 s) — derived from `wave_len` so it adapts to FT8 vs FT4 — preventing a stalled TX path (`tx_idx` never reaching `wave_len`) from leaving MOX stuck on.
- **`ft8_qso.c/h`** — FT8 **auto-QSO state machine** (Phase 2). Polls the decoder every ~500 ms (GTK thread), drives the standard WSJT-X exchange (CQ → grid → report → R-report → RR73 → 73), keys TX on the opposite slot, and appends completed QSOs to `~/.local/share/machpsdr/ft8_log.adi` (ADIF). Also: `Enable Tx`/`Auto Seq` gates, manual `Tx1..Tx6` (`ft8_qso_select_tx`) and free text (`ft8_qso_send_free`), worked-before lookup from the ADIF log (`ft8_qso_worked`), and a 6-minute Tx watchdog. Station call/grid + TX offset/slot live on `RADIO` (`station_call`, `station_grid`, `ft8_tx_offset`, `ft8_tx_even`), persisted in `radio_save_state`. Each completed QSO is also pushed to a network logger via `ft8_udp_log()` (see `ft8_udp.c`). **Logbook / worked tracking:** `log_qso` writes an ADIF `BAND` field (in addition to `FREQ`), derived from the dial via `band_from_hz()`. On start-up `worked_load` reads the log one record per line (`adif_get`) and, besides the worked-call set (`worked`), builds two DXCC sets: `worked_dxcc` (entity worked on **any** band) and `worked_dxcc_band` (key `band*1000+ent`, per-band); older records with only `FREQ` still get a band. `ft8_qso_new_dxcc(call)` = new entity ever, `ft8_qso_new_dxcc_band(call, dial_hz)` = new on that band — both back the panel's two-level "new one" highlight. `ft8_qso_country()` returns the cty.dat country name. **Directed CQ:** `msg_cq` (and the Tx6 message) prepend an optional modifier from `RADIO.ft8_cq_dir` → `CQ <dir> CALL GRID` (region like DX/EU/NA or a 3-digit `nnn`, per the FT8 `CQ a[bcd]`/`CQ nnn` codec support); blank = plain CQ. Set from the panel's config-row combo; persisted in `radio_save_state`. **FT4:** the exchange logic (identical 77-bit payloads) is protocol-agnostic; only `slot_even_from_utc()` (slot = seconds-of-day×2/15 for FT4's 7.5 s slots) and the ADIF `MODE` field (`FT4`/`FT8` from `radio->ft8_proto`) are protocol-aware. The `MODE` propagates to the network logger automatically (`ft8_udp_log` forwards the record verbatim).
- **`ft8_udp.c/h`** — **Network QSO logging** (JTDX/WSJT-X compatible). `ft8_udp_log()` sends the completed QSO's ADIF record as a WSJT-X UDP "ADIF" message (magic `0xadbccbda`, schema 2, message type 12; big-endian, uint32-length + UTF-8 strings) to a configurable host:port, so QSOs appear in a logger (Log4OM, N1MM+, JTAlert, GridTracker) over the network. Gated by `radio->ft8_log_udp`; host/port in `radio->ft8_log_udp_host`/`ft8_log_udp_port` (default `127.0.0.1:2237`), all persisted in `radio_save_state`.
- **`ft8_pskreporter.c/h`** — **PSK Reporter spot reporting.** `ft8_pskreporter_report()` is called from the decoder worker (`ft8_decoder.c:decode_slot`) once per 15 s slot and sends every decoded station as a reception report to `report.pskreporter.info:4739` (UDP), the same network WSJT-X/JTDX feed — so the operator's spots appear on the PSK Reporter map. Wire format is PSK Reporter's IPFIX protocol (private enterprise number 30351): a message header, a receiver-information options template (`0x50E2`: receiverCallsign/Locator/decodingSoftware/antennaInformation) and a sender/reception-record template (`0x50E3`: senderCallsign/frequency(5B)/sNR(1B)/mode/senderLocator/informationSource(1B)/dateTimeSeconds), both re-sent each packet, followed by the receiver data record and one sender record per spot. RF frequency = the active RX dial (`frequency_a`) + the decode's audio offset; `senderLocator` is filled only when the decode's `extra` is a Maidenhead grid; free-text/telemetry decodes (no `call_de`) and self-spots are skipped. **Gated by `radio->ft8_pskr` AND a non-empty `station_call` + `station_grid`** (per the user requirement — nothing is sent until both identity fields are set). Enabled via a checkbox in Configure → FT8 (`ft8_dialog.c`); `ft8_pskr` persisted in `radio_save_state`. Packet layout byte-verified with an IPFIX round-trip parser. The reported `mode` string follows `radio->ft8_proto` (`FT4`/`FT8`). Compiled only with the `FT8` flag.
- **`ft8_waterfall.c/h`** — **Dedicated FT8 band waterfall** (JTDX-style). Self-contained spectrogram of just the FT8 audio passband (0–3000 Hz): a windowed 4096-pt real FFT (`kiss_fftr`) of the decoder's 12 kHz audio ring via `ft8_decoder_get_spectrum()` (in `ft8_decoder.c`) → ~2.93 Hz/bin, fine enough to separate FT8 tones. Renders a scrolling `GdkPixbuf` coloured with `get_waterfall_color()` (the active RX's `waterfall_color_theme`), with a 500 Hz frequency grid and a green TX-offset marker. The marker is a base-tone line plus a **translucent band spanning the signal's occupied bandwidth**, which is protocol-dependent (FT8 = 8 tones × 6.25 Hz ≈ 50 Hz; FT4 = 4 tones × 20.83 Hz ≈ 83 Hz, from `radio->ft8_proto`) so picking a clear TX slot is honest for FT4's wider footprint; the label reads `TX`/`FT4`. **Independent of the main WDSP analyzer** (no `SetAnalyzer`/`dMAX_PIXELS` limit), so it gives real per-Hz zoom the `pixels=width×zoom` main panadapter can't. **Left-click sets the FT8 TX offset** directly on a clear frequency. Its own ~14 fps `g_timeout`, torn down on `destroy`. **Placement:** to the **right of the active receiver's RF spectrum (~1/3 width)**. The RF spectrum (`rx->vpaned`) is wrapped in a **windowless horizontal `GtkBox`** (`rx->wf_hpaned` — a box, despite the name); `receiver_ft8_waterfall_sync()` (`receiver.c`) packs/removes the FT8 waterfall as its second child, sized to 1/3 of the row by an `ft8_wf_box_alloc` size-allocate handler that tracks resizes. A `GtkBox` is used deliberately, **not** a `GtkPaned`: wrapping `vpaned` in a `GtkPaned` blanked the main waterfall (window-hierarchy quirk), whereas the windowless box leaves the vpaned's `GdkWindow` parenting unchanged. Shown only when the RX is in **DIGU *and* the FT8 panel is open** (`radio->ft8_panel_open`) — hooked from `receiver_mode_changed`, `radio_ft8_panel_sync`, and once after `create_visual`. **Span:** follows the DIGU receive filter width (`filter_low_a/high_a`), clamped to 0.5–5 kHz (`wf_span_hz`); `ft8_decoder_get_spectrum` returns up to 5 kHz and the widget shows the filter sub-span, rescaling its content to any width on resize. The old main-panadapter FT8 auto-zoom was removed (this waterfall replaces it).
- **`ft8_dxcc.c/h`** — **DXCC entity resolver** (backs the "new one" highlight). Parses AD1C's `cty.dat` country file (bundled in the repo root; ~346 entities) into an exact-callsign hash plus a prefix hash, and `ft8_dxcc_entity(call)` returns a DXCC entity index by exact-call override else **longest-prefix** match (faithfully reproducing cty.dat precedence — e.g. `UA9X…`→European Russia via the 4-char district prefix while bare `UA9`→Asiatic Russia; portable `SV9/DL1XX` handled by scanning `/`-segments). - **`sstv_decoder.c/h`** — **SSTV image receive decoder** (Martin / Scottie / Robot / PD). Self-contained analogue-SSTV decoder with **no external DSP dependency** (no WDSP/FFT). Tapped in `receiver.c:process_rx_buffer` on the active RX's 48 kHz demod audio whenever it is in **DIGU/DIGL** (HF SSTV over SSB) **or FMN** (VHF/ISS SSTV over narrowband FM — the ISS transmits on 145.800 MHz FM, so Robot 36/PD120 need the RX in FMN; the audio-subcarrier discriminator is amplitude-independent so FM de-emphasis doesn't hurt it) *and* `radio->decode_mode==DECODE_SSTV`. `decoder_taps_audio()` and the bottom-bar selector/`Show SSTV`/panel gating all special-case FMN for SSTV (FT8/FT4 stay SSB-only) (the shared decoder-tap machinery — unity WDSP panel gain so the tap always sees full level, plus software listen-volume — is now compiled under `#ifdef DECODERS` = `defined(FT8) || defined(SSTV)`, not just FT8). Pipeline: a **51-tap windowed Hilbert-FIR FM discriminator** turns the audio into instantaneous frequency (1500 Hz = black .. 2300 Hz = white, 1200 Hz = sync) written into an absolute-indexed inst-freq ring; a **VIS-header detector** (1900 Hz leader → 1200 Hz start bit → 8×30 ms bits, even-parity checked) auto-selects the mode; then a family-dispatched **per-line decoder** reconstructs the image. **Modes** (`MODES[]`, N7CXI timings), five **families**: **Martin M1/M2** + **Scottie S1/S2/DX** (`FAM_MARTIN`/`FAM_SCOTTIE`, direct **GBR**), **Robot 36** (`FAM_ROBOT36`, YUV 4:2:0 — Y each line + **alternating** R-Y/B-Y whose Y/chroma separator tone encodes which, paired across two rows), **Robot 72** (`FAM_ROBOT72`, YUV 4:2:2 — Y+R-Y+B-Y every line), and **PD50/90/120/160/180/240** (`FAM_PD`, YUV 4:2:0 — **two image rows per transmitted line**: Y0, R-Y, B-Y, Y1). YUV→RGB is full-range BT.601 (`put_yuv_row`). Geometry is per-mode (`img_w`/`img_h`, up to 640×496 for PD120/180/240); the RGB buffer is `MAX_W*MAX_H*3`. **This covers ISS SSTV: Robot 36 (MAI-75) and PD120 (ARISS).** GBR sync placement differs by family — **Martin** sync at line start (offsets positive), **Scottie** sync between blue and red (green/blue read from *before* the located sync, red *after*). **Per-line sync locking** (`locate_sync`, ±12 ms min-|f−1200| search) re-anchors every line to cancel clock offset/slant; **line 0 is anchored on VIS-derived timing, not searched** — the first sync abuts the 1200 Hz VIS stop bit (Martin/Robot/PD) so a search would lock onto the stop bit. A separate **`tx_line`** counter (distinct from the image-row `cur_line`) drives the sync prediction/re-lock, because PD emits two rows per transmitted line. **VIS robustness (from real-signal debugging):** the 1900 Hz leader is **latched** (`leader_deadline`) once ≥180 ms is seen — a raw consecutive-run counter is reset by the finite-slope glide between the 1900 Hz leader and the 1200 Hz start bit on real signals (synthetic tones switch instantly, so this only bit off-air), and both `vis_pending` and `cand_start` are frozen while a header buffers its bits so image content can't re-latch and clobber the pending decode. **Two offset-tolerant start paths besides VIS** (both detect the sync on its falling edge with a plausible-length gate, so the ~300 ms VIS field — whose 1100/1300 Hz bits all fall inside the ±250 Hz sync band — is rejected instead of false-anchoring): **(a) forced-mode sync anchor** — `sstv_decoder_set_mode(vis)` (panel combo) skips the VIS and anchors line 0 on the first clean sync pulse; **(b) automatic line-period detection** (auto mode) — collects 5 consecutive sync pulses and, when their spacing is consistent, matches it to the closest mode's line period (`line_period_of`, within 2 %) and starts. Both are the reliable path for **FM/VHF SSTV (ISS)**, where WDSP's FMN de-emphasis smears the fast 30 ms VIS bits into an unreadable header even though the image itself (slower transitions) decodes cleanly — so **Auto works on ISS** without the operator picking a mode. Verified on the real ISS recording in both auto and forced modes, and at ±200 Hz mistune. **Verified on a real ISS PD120 recording** (ARISS Sputnik commemorative image decoded correctly from off-air FM audio). **Auto-slant:** the per-line residual `sync − pred` is the clock error (true line period − assumed); a servo folds it back into `line_samples` (clamped ±5 %) and scales the pixel clock (`clock_scale`, applied in `pixel_smp()`), so a sound-card / sample-rate offset that would slant the picture is removed automatically without operator intervention — the manual `Slant ±` (`slant_ppm`, now a fine ±20 ppm trim) remains as an additional trim on top. **AFC (automatic frequency correction):** mistuning / ISS Doppler shifts every audio tone equally, which without correction washes the whole picture lighter/darker (1500 Hz black slides off the scale) *and* would break sync detection. So `freq_offset` is **seeded** from the anchoring sync pulse (the forced-mode sync gate is widened to ±250 Hz for this) and then tracked line-by-line from each located sync (a known 1200 Hz reference, guarded so a free-run line can't poison it); `freq2val()` subtracts it (brightness) and `locate_sync()` targets `F_SYNC + freq_offset`. Verified to **±200 Hz** offset (brightness within ~2 levels of the tuned reference). Exposed via `sstv_decoder_get_afc()` → the panel shows `(AFC ±N Hz)` so the operator knows to nudge the dial. The image lives in a mutex-protected RGB byte buffer; `sstv_decoder_get_image()` (GTK thread) returns a fresh `img_w×img_h` `GdkPixbuf` copy. `sstv_decoder_set_mode(vis)` forces a mode (0 = auto); `sstv_decoder_adjust_slant(dppm)` trims the pixel clock. All decode runs inline on the RX audio thread (atomic no-op when disabled). Compiled only with the `SSTV` flag. Verified end-to-end with a synthetic colour-bar generator (Martin M1, Scottie S1, Robot 36, Robot 72, PD120 → **8/8 bars pixel-correct each**).
- **`sstv_encoder.c/h`** — **SSTV image TX encoder** (the mirror of `sstv_decoder.c`). Encodes a `GdkPixbuf` (fitted to the mode's native geometry by `letterbox()` — aspect-ratio-preserving scale onto a black canvas, so a non-matching source is letter-/pillar-boxed, not stretched) into an analogue-SSTV audio **tone timeline** — a standard VIS header (1900 Hz leader / 1200 Hz break / leader / start bit / 7 data bits LSB-first, 1100 Hz=1 / 1300 Hz=0 / even parity / stop bit — the exact inverse of `decode_vis()`) followed by per-line sync / porch / separator tones and the FM-encoded pixel scans (`val2freq`: 1500 Hz=black .. 2300 Hz=white). Same `MODES[]` timings as the decoder (renamed **`TX_MODES[]`** in this file because `mode.h`, included here for `DIGU`/`DIGL`/`FMN`, defines a `MODES` enum constant). Five family builders mirror the decoder: **GBR** (`build_gbr` — Martin `sync,porch,G,sep,B,sep,R,sep`; Scottie `sep,G,sep,B,sync,porch,R` with a leading start sync on line 0), **Robot 36** (`build_robot36` — Y each line + alternating R-Y/B-Y, the Y/chroma separator tone 1500/2300 Hz encoding which), **Robot 72** (`build_robot72` — Y+R-Y+B-Y), **PD** (`build_pd` — two image rows per line Y0,R-Y,B-Y,Y1, chroma from the vertical average of the row pair). RGB→YCbCr is full-range BT.601 (`rgb_y`/`rgb_cr`/`rgb_cb`, the exact inverse of the decoder's `put_yuv_row`). **Playback:** the timeline is a list of `{float freq; float dur_ms;}` segments built on the GTK thread (`sstv_tx_prepare`); the audio thread walks it in `sstv_tx_next_sample()` with a phase accumulator, deciding segment boundaries from a **cumulative double sample count** (`seg_end_smp`) so the fractional per-pixel duration never accumulates integer-rounding drift (which would slant the picture). A raised-cosine envelope suppresses key clicks at the start/end. **TX integration:** `add_mic_sample()` (`transmitter.c`) substitutes `sstv_tx_next_sample()` for the mic input whenever `sstv_tx_active()` (any phone mode — DIGU/DIGL modulate it as SSB, FMN as FM; universal across protocol1/2/soapy), exactly like the FT8 encoder's DIGU substitution. `sstv_tx_start()` (GTK thread) validates `radio->can_transmit` + the active RX mode ∈ {DIGU,DIGL,FMN}, keys MOX (`set_mox`), and starts a ~100 ms `g_timeout` tick that drops MOX when the waveform finishes and enforces a **MOX safety watchdog** (`total_ms + SSTV_TX_MARGIN_MS`) so a stalled TX path can't leave MOX stuck on. Self-contained (no WDSP/FFT). **Verified** by an encode→decode loop-back harness (Martin M1, Scottie S1, Robot 36/72, PD120 → 8/8 colour bars pixel-correct via the decoder's VIS path). Note: the decoder's *forced-mode* sync anchor (path 3b) false-triggers on the standard 10 ms VIS break, so a round-trip on this app should use **Auto** (VIS) decode — the recommended default anyway. Compiled only with the `SSTV` flag.

- **`wefax_decoder.c/h`** — **WEFAX / HF-radiofax image receive decoder.** The shortwave analogue-fax cousin of `sstv_decoder.c`: weather charts / satellite images broadcast on HF (DWD, Northwood, …), received in **DIGU/DIGL** (USB). Reuses the exact SSTV tone convention (**1500 Hz = black .. 2300 Hz = white**) and the same **51-tap Hilbert-FIR FM discriminator** → instantaneous-frequency ring (`freq2val` maps to 0..255, AFC-corrected), but the format differs fundamentally: a **continuous scan** (no fixed frame height — the image grows in a scrolling `BUF_H`-row buffer, top third scrolls off when full) with **no VIS header**. Line sync comes from the transmission's own signals instead: an **automatic start-tone detector** (the black/white square-wave start signal — **300 Hz for IOC 576 / 675 Hz for IOC 288**, counted as low→high crossings per 1-second block; a match begins a fresh page via `begin_page()`, sets the IOC and **seeds the AFC** from that block's bimodal black/white level means; a `start_cooldown` prevents the multi-second tone from re-triggering), then **continuous auto-phasing** (`p_autophase`, default on) that **self-aligns** the picture with no operator input: it accumulates a per-column EMA of the edge energy (`col_energy[IMG_W]`, `A=1/12`) — a vertical feature recurring at the same column every line (the fax margin/border, or a grid line) builds a sharp peak while random picture content (coastlines/text) spreads to a flat floor — and after ~24 lines (`acq_lines`), when a clear peak has formed (`peakv>40 && peakv>3·mean`), applies a **single** shift to bring that peak to the left edge and **freezes** (`phase_locked`). Crucially the alignment is *one-time*, not a per-line servo — a per-line phase correction would itself be a slant (a row-dependent horizontal shift, which it was in a first cut — it visibly skewed the picture); acquiring once and holding keeps verticals straight. A start tone (`begin_page`) or Clear resets `acq_lines`/`phase_locked` so a new page re-acquires. Line period from **LPM** (`SR*60/lpm`; 60/90/120/240), each line resampled to a fixed `IMG_W` (**1810** ≈ the native IOC576 element count `576·π`, so thin chart lines are resolved ~1 element/pixel instead of being undersampled to faint grey at the old 800 — this was the fix for a "faint contours, barely readable" report; the panel scales the wide image to fit with `CAIRO_FILTER_GOOD` so downscaling keeps the lines, and needs a **wide enough RX/demod filter ~1.9 kHz** upstream or the fast black↔white transitions smear); **slant** (ppm trim) and a **manual phase nudge** (`wefax_decoder_nudge_phase`, fraction of a line — the panel passes the clicked column, used when Auto-phase is off) refine alignment. **Quality helpers (both default on):** (1) **one-time white-anchored AFC** — a weather chart is predominantly white, so the dominant frequency over the first ~24 lines of a page (a coarse `freq_hist`) is the white level; anchor it to 2300 Hz *once* then freeze (`afc_done`). This corrects mistuning/drift without a continuous loop (a continuous midpoint-tracking AFC was tried first and drifted grey — the black percentile is biased on a mostly-white chart, and it chases noise during fades). The start-tone path seeds AFC itself and sets `afc_done` so the histogram estimate is skipped. (2) **Conditional-median despeckle** (`p_denoise`) — replaces only pixels that are an isolated spike vs *both* horizontal neighbours (FM-click impulse noise), leaving real edges / thin lines (which agree with one neighbour) untouched. Whole-line fade streaks (a deep-QSB line that is all noise) are inherent to the recording and not removed by either. Free-runs continuously once enabled (so the operator always sees a rolling image even without a start tone). Public API mirrors the SSTV decoder (`wefax_decoder_set_enabled/add_audio/set_lpm/set_ioc/set_autostart/start/reset/adjust_slant/get_afc/get_status/get_image`). Tapped in `receiver.c:process_rx_buffer` alongside the SSTV tap (HF USB only). Self-contained (no WDSP/FFT); runs inline on the RX audio thread, image in a mutex-protected RGB buffer. Compiled only with the `SSTV` flag. **RX only** (no TX encoder). Verified end-to-end with a synthetic generator (start tone → phasing → gradient + vertical bar): start-tone/IOC/AFC detected, phase-locked (straight, un-slanted lines), gradient orientation and bar position correct.

- **`ext.c`** — Thread-safe UI dispatch helpers (`ext_*` functions wrap `g_idle_add()` calls)
- **`log.c/h`** — **Levelled console logging.** Three levels `ERROR < INFO < DEBUG`; macros `log_error()`/`log_info()`/`log_debug()` all write to **stderr**, line-serialised by a mutex (safe from the audio/protocol/decoder threads) and prefixed with the level (`[INFO] …`). The level guard lives in the macro (a single int compare against `machpsdr_log_level`), so a `log_debug()` on a hot path costs nothing — and its args are never evaluated — when DEBUG is off. Threshold defaults to **INFO** and is set at start-up in `main.c` from `MACHPSDR_LOG=error|info|debug` (env) then overridden by the CLI (`--log-level <lvl>` / `--log-level=<lvl>`, `--debug`/`-v`/`--verbose`, `--quiet`/`-q`); `log_set_level_name()` parses the names. **All former `g_print`/`fprintf(stderr,…)`/`printf` calls across the app were migrated to these macros** (errors→`log_error`, status/chatter→`log_info`, hot-path & per-slot traces→`log_debug`); the vendored `ft8_lib/` and `wdsp/` trees were left untouched. New code should use the `log_*` macros, not bare `printf`/`g_print`.

### UI Dialogs
All dialogs follow the `*_dialog.c/h` naming convention: `radio_dialog`, `receiver_dialog`, `transmitter_dialog`, `midi_dialog`, `configure_dialog`, `bookmark_dialog`, `diversity_dialog`, `pa_dialog`, `eer_dialog`, `puresignal_dialog`, etc.

### Threading
Background tasks (protocol I/O, wisdom file creation) use `GThread`. UI updates must be dispatched to the GTK main thread via `g_idle_add()` or the `ext_*` wrappers in `ext.c` — never call GTK functions directly from protocol/audio threads.
