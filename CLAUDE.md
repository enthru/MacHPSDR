# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MacHPSDR is a GTK4-based SDR (Software Defined Radio) control application for HPSDR hardware, written in C. It is a personal fork of [LinHPSDR](https://github.com/g0orx/linhpsdr) by John Melton (G0ORX/N6LYT), with a primary focus on macOS compatibility and several feature additions (freetune mode, waterfall themes, ppm correction, att10/att20 filter control, etc.). Licensed under the GNU GPL (v2 or later); see `LICENSE` and `NOTICE`.

The binary, install paths and config directory use the lowercase name `machpsdr`; the display name (window title, About dialog, `.app` bundle) is `MacHPSDR`.

## Build Commands

```bash
# Build the binary
make

# Install to /usr/local/bin
sudo make install        # Linux
make install             # macOS

# Clean build artifacts
make clean

# Build self-contained macOS .app bundle (requires dylibbundler)
make app
open MacHPSDR.app
```

No automated test suite exists — testing is manual with physical hardware. For
hardware-free smoke testing there is a synthetic **fake device**: run
`./machpsdr --faker <iq.wav>` (e.g. `--faker ft8.wav`) to loop an I/Q recording
through the full RX/decoder chain. With `--faker` the device-selection dialog is
skipped and the fake radio starts straight up, so it can be launched headless
(e.g. under lldb). See `fake_protocol.c` and the flag parsing in `main.c`.

## Dependencies

### macOS (via Homebrew)
```bash
brew install fftw gtk4 gnome-icon-theme libsoundio libffi soapysdr dylibbundler
```

### Linux (via apt)
```bash
sudo apt-get install libfftw3-dev libpulse-dev libsoundio-dev libasound2-dev libgtk-4-dev libsoapysdr-dev
```

### WDSP (vendored — do NOT install upstream)
The patched WDSP this fork needs is vendored in-tree under `wdsp/` and is built
automatically by `make` on **both platforms** (`wdsp/libwdsp.dylib` on macOS,
`wdsp/libwdsp.so` on Linux); the binary finds it via rpath (`@loader_path/wdsp`
on macOS, `$ORIGIN/wdsp` on Linux). Do **not** `git clone g0orx/wdsp` and
`sudo make install` it — a stock system `-lwdsp` compiles but silently breaks
this fork's WFM demod and other DSP patches. The Makefile's `wdsp-local` target
(`$(MAKE) -C wdsp`) is an order-only prereq of the main binary on both platforms.

## Platform Differences

- **macOS**: Uses `audio.c` (SoundIO + CoreAudio) for audio, `mac_midi.c` for MIDI (CoreMIDI framework), no CWDAEMON support
- **Linux**: Uses `audio.c` with ALSA/PulseAudio/SoundIO, `alsa_midi.c` for MIDI, CWDAEMON enabled by default

> Note: `audio.c` is the audio backend on **both** platforms. The Makefile's `AUDIO_SOURCES=portaudio.c` (Darwin) is a dead variable — `portaudio.c` does not exist and is never compiled; `audio.c` is hardcoded in `SOURCES`/`OBJS`.

Platform is detected via `uname -s` in the Makefile (`Darwin` vs `Linux`).

## Build Feature Flags (Makefile)

| Flag | Default | Notes |
|------|---------|-------|
| `SOAPYSDR` | enabled | RTL-SDR/LimeSDR/HackRF support (RX; HackRF TX implemented, half-duplex, untested on hardware) |
| `MIDI` | enabled | MIDI controller support |
| `CWDAEMON` | enabled (Linux only) | CW keying via unixcw |
| `PURESIGNAL` | disabled | Adaptive distortion correction (Protocol 1 only) |
| `OPENGL` | disabled | OpenGL rendering |
| `FT8` | enabled | FT8 RX decoder + TX/auto-QSO (decoder auto-enabled in DIGU; big QSO panel is opt-in via a bottom-bar toggle); vendored `ft8_lib/` |
| `SSTV` | enabled | SSTV image RX decoder **and** TX encoder (Martin/Scottie/Robot/PD, incl. ISS Robot 36 & PD120) + embedded image panel; **also gates the WEFAX / HF-radiofax RX decoder** (`wefax_decoder.c`/`wefax_panel.c`); self-contained (no external DSP) |

To toggle, comment/uncomment the `*_INCLUDE=*` lines near the top of the Makefile.
`DECODERS` = `defined(FT8) || defined(SSTV)` gates the shared decoder-tap machinery.

## Source Layout

The ~90 first-party `.c/.h` live under `src/<subsystem>/`; the repo root holds
only the Makefile, `README`/`LICENSE`/`NOTICE`/`CLAUDE.md`, `mac-setup.sh` and
`machpsdr.desktop`. Program resources live in **`assets/`** (the PNG icons +
`cty.dat`) and screenshots/migration notes join the user manuals in **`doc/`**. The runtime lookups
that used to read `machpsdr.png` / `cty.dat` from the cwd now try `assets/`
first (see `main.c` icon path and `ft8_dxcc.c:open_cty`), and `make app` copies
them from `assets/`; the bare-cwd fallbacks are kept for older layouts.

| Dir | Contents |
|-----|----------|
| `src/core/` | app lifecycle + central state + fundamentals: `main`, `radio`, `receiver`, `transmitter`, `subrx`, `ext`, `error_handler`, `log`, `version`, `property`, `actions`, `vox`, `mode`, `filter`, `band`, `frequency`, `ringbuffer`, and the pure headers (`agc.h`, `adc.h`, `dac.h`, `alex.h`, `bandstack.h`, `channel.h`) |
| `src/proto/` | hardware comms + discovery: `protocol1/2`, `*_discovery`, `soapy_*`, `fake_protocol`, `discovery`, `discovered`, `reconnect`, `hl2`, `rigctl`, `puresignal`, `cwdaemon` |
| `src/dsp/` | `bpsk`, `diversity_mixer`, `peak_detect`, `ppm_cal` |
| `src/audio/` | `audio`, `recorder` |
| `src/midi/` | `midi2/3`, `midi_dialog`, `mac_midi`, `alsa_midi`, `midi.h` |
| `src/ui/` | all widgets/dialogs/spectrum: `*_dialog`, `*_panadapter`, `waterfall*`, `wideband*`, `vfo`, `meter`, `level_meter`, `tx_info*`, `radio_info`, `mic_*`, `drive_level`, `button_text`, `settings_ui`, `bookmark_dialog`, `css`, `gpu_image`, `waterfall_theme` |
| `src/decode/` | `ft8_*`, `sstv_*`, `wefax_*` (decoders/encoders/panels) |

Vendored trees (`wdsp/`, `ft8_lib/`) are untouched at the repo root.

**Build mechanism:** the Makefile stays path-agnostic. `VPATH` (set to `$(SRCDIRS)`)
lets `make` resolve the bare `foo.c` names in `OBJS`/`SOURCES` from any subsystem
dir, and every dir is on the `-I` path (`SRC_INCLUDES`), so the flat
`#include "radio.h"` style keeps working with no per-file edits (all header
basenames are unique). Objects still build into the repo root as gitignored
`*.o`/`*.d`, so `OBJS` entries remain bare `foo.o` names. To add a new source,
drop it in the right `src/` dir and add its bare `foo.o` to `OBJS` (or the
relevant feature `*_OBJS`) as before — no path prefix.

## Architecture

### Application State
The global `RADIO *radio` struct (`radio.h`) is the central application state. It holds references to up to 8 `RECEIVER` structs, one `TRANSMITTER` struct, and hardware/protocol configuration.

### Key Modules

- **`main.c`** — Entry point, GTK init, device discovery, main window creation. The window is brought to the foreground on startup (`gtk_window_present` + a macOS-only `activateIgnoringOtherApps:YES` sent via the Obj-C runtime — AppKit is already in-process via GTK's quartz backend, so no framework link / `.m` file is needed), so it doesn't open hidden behind the launching terminal (matters most under `--faker`). Also sets the log level (see `log.c/h`) and calls `ft8_dxcc_init()` before `ft8_qso_init()`.
- **`radio.c/h`** — Radio lifecycle management, hardware model definitions (ANAN, Hermes, Hermes-Lite, Orion, Atlas, etc.). Owns the bottom-bar Decode block and its mode-gated decoder selector (see the decoder-selection notes below), the FT8/SSTV/WEFAX panel sync helpers (`radio_ft8_panel_sync` / `radio_sstv_panel_sync` / `radio_wefax_panel_sync`, all mutually exclusive over the second-RX slot), `radio_rebuild_rx_stack`, and the `radio_ppm_correction()` helper. State persisted in `radio_save_state`.
- **`receiver.c/h`** — Per-receiver state: VFO A/B, AGC, NR/NB/ANF, filters, modes, panadapter/waterfall.
  - **Analyzer-feed heap-safety invariant:** WDSP's `Spectrum0()` writes each transfer block into a fixed I/Q input ring (`WDSP_ANALYZER_MAX_SIZE`×2 = 2¹⁹ complex samples) and only wraps at the ring end, so **the transfer block must divide the ring exactly** (see `// REQUIRES buff_size IS A SUB-MULTIPLE…` in `wdsp/analyzer.c`) or the last block before the wrap corrupts the heap. The wideband RX block (5120) and the widest TX block (40960) do **not** divide 2¹⁹, so the panadapter feed goes through `analyzer_feed()`, which splits any buffer into `ANALYZER_FEED_BLOCK` (1024 = gcd(5120,2¹⁹)) sub-blocks; `SetAnalyzer` is configured with `bf_sz == ANALYZER_FEED_BLOCK`. A `_Static_assert` in `receiver.h` enforces divisibility at compile time. (`bpsk.c` 2048 and `wideband.c` 16384 already use ring-dividing blocks.)
  - **Panadapter/waterfall vertical split (`vpaned`):** panadapter (top) has `MIN_PANADAPTER_HEIGHT` (90) with `shrink_start_child=FALSE`; `restore_paned_position_cb` waits for a usably-tall pane (bounded retries via `paned_restore_tries`) then clamps the split so both children keep their minimums. The panadapter can be turned off per receiver (`rx->show_panadapter`, persisted): `receiver_apply_panadapter_visibility()` hides it so the waterfall takes the whole height, and `waterfall.c:resize_timeout` then mirrors its own width into `panadapter_width`/`pixels` and re-runs `receiver_init_analyzer()` so the spectrum feed keeps working (the panadapter normally drives the bin count via `rx->pixels = panadapter_width × zoom`).
  - **Per-mode filter memory:** `rx->mode_filter[MODES]` remembers each mode's selected filter slot (previously a single shared `rx->filter_a` meant narrowing AM also narrowed SSB). `receiver_mode_changed()` saves the outgoing mode's slot and restores the incoming one, `receiver_filter_changed()` keeps it in sync, persisted per receiver (older configs re-sync `mode_filter[mode_a]=filter_a` on load).
  - **Per-mode AGC memory:** `rx->mode_agc[MODES]` remembers each mode's AGC speed (OFF/LONG/SLOW/MEDIUM/FAST) the same way — `receiver_mode_changed()` saves the outgoing mode's `agc` and restores/`set_agc()`s the incoming one, and the AGC-change paths (`agc_cb` in `vfo.c`, the `AGC` action in `actions.c`) keep `mode_agc[mode_a]` in sync. Persisted per receiver; older configs re-sync `mode_agc[mode_a]=agc` on load. The VFO's AGC button label follows automatically via `vfo_update`.
  - **Tuning limits:** `receiver_move_a`/`receiver_move_b` clamp tuning to `[0, receiver_max_frequency()]`, where the max is a hard **6 GHz** ceiling (HackRF's top end + a sanity cap that stops a runaway digit edit producing a garbage frequency), lowered to `radio->discovered->frequency_max` when the device is narrower (e.g. ~61 MHz classic HPSDR). The ctun/freetune path guards `ctun_frequency`, the normal path guards `frequency_a`. The guard is **directional**: it rejects only moves that push *further* outside `[0, fmax]`, so a dial already above the device max (a restored config, an xvtr/VHF frequency, or a wideband recording centred at VHF) can always still be tuned back down toward the valid range instead of being frozen solid.
  - **Decoder tap:** `process_rx_buffer` feeds whichever decoder `radio->decode_mode` selects; the raw off-air I/Q taps for the recorder and PPM cal are in `full_rx_buffer`/`full_diviqrx_buffer`. `decoder_taps_audio()` reports when a decoder is active, in which case `rx_panel_gain()` forces WDSP panel gain to unity so the tap sees full level and the listen volume/mute is applied in software.
- **`transmitter.c/h`** — TX path: filtering, CTCSS, EER, PureSignal, metering. The TX panadapter feed uses `analyzer_feed()` for the same heap-safety reason (the 1920 kHz span's 40960-sample block doesn't divide 2¹⁹). `add_mic_sample()` substitutes the FT8/SSTV encoder output for the mic input while an encoder is active (universal across protocol1/2/soapy).
- **`protocol1.c`, `protocol2.c`, `soapy_protocol.c`** — Hardware communication for Classic HPSDR, enhanced protocol, and SoapySDR devices. **PPM correction** (`radio->ppm_correction_value`, a **`double`**, ±500 ppm) is applied in the RX/TX tune-frequency computation of all three via `radio_ppm_correction(f_rf)` (`radio.c`; returns `llround(f_rf*ppm/1e6)`, `f_rf` = dial−LO). Protocol 1 reads it live in its output thread; Protocol 2 / SoapySDR pick up a change on the next `frequency_changed()` retune. Persisted as `%f` (older integer props load via `atof`).
- **`ppm_cal.c/h`** — **PPM (oscillator) calibration against time-signal stations.** Holds the reference-station table (`PPM_STATION` name+carrier Hz — RWM/WWV/CHU/BPM on HF, MSF/DCF77/Droitwich on LF) and `ppm_cal_tune_to_station()` (parks the active RX on the carrier in CW-USB for zero-beating by ear). **Automatic measurement:** `ppm_cal_measure_start()` retunes so the carrier lands at `PPM_MEAS_OFFSET` (1500 Hz, clear of DC); `ppm_cal_iq_feed()` (tap in `receiver.c` on raw off-air I/Q) accumulates `PPM_FFT_N`(32768)-pt frames, runs a self-contained radix-2 FFT, finds the carrier bin, parabolic-interpolates to sub-bin (~0.1 Hz), and averages `PPM_FRAMES`(6) frames (SNR-gated, skipping `PPM_SETTLE` after retune). Closed-loop: `ppm_new = ppm_old + (residual_Hz/(carrier−lo))·1e6` where `residual = measured − PPM_MEAS_OFFSET`; sign follows the HPSDR non-inverted I/Q convention. Runs on the RX audio thread (atomic no-op when idle); the UI polls `ppm_cal_measure_poll()`. The RX's VFO/mode/filter are saved at start and restored by `ppm_cal_restore_rx()`. UI in **Configure → Misc** (`labels_dialog.c`, "Frequency Calibration (PPM)" frame): ppm spinner + station combo + **Calibrate**/**Tune** buttons; **Calibrate** doubles as **Stop** while running.
- **`discovery.c`, `protocol1_discovery.c`, `protocol2_discovery.c`, `soapy_discovery.c`** — Network device discovery.
- **`vfo.c`** — Frequency display and VFO control widget. Zoom menu (quick x10/x12/x16/x32 jumps; app-wide cap is 32× — see zoom note under `ft8_panel.c`). **Mouse-wheel tuning:** wheel-up tunes up, wheel-down tunes down, stepped by the digit under the cursor (same convention for VFO A/B and ctun). The digit under the pointer is found by `freq_digit_at()`, which hit-tests the label's real Pango layout (`gtk_label_get_layout` + `pango_layout_xy_to_index`, offset by `gtk_label_get_layout_offsets`) instead of assuming uniform character cells across the full widget width — accurate regardless of label alignment/padding. **SDR#-style digit entry:** the freq-label motion handlers record the hovered receiver/VFO/digit (`freq_hover_rx`/`freq_hover_digit`/`freq_hover_is_b`, cleared on pointer leave); `vfo_type_digit()` (called from `receiver_key_pressed` in `receiver.c`) overwrites that digit in place when a number key is pressed and advances the cursor one digit right. **Type-in frequency panel:** a **primary (left) click** on either VFO frequency opens `vfo_show_freq_entry()` — a modal `GtkPopover` with a pre-focused `GtkEntry`; typing a frequency in **MHz** (`vfo_parse_freq()` accepts `.`/`,` and the grouped `14.074.000` style) and pressing Enter calls `vfo_apply_frequency()`, which sets the absolute frequency via `receiver_move[_b]` (so it honours ctun/freetune sign and the `[0, 6 GHz]` guards). The band-stack menu moved to the **secondary (right) click**.
- **`meter.c`** — Analog S-meter widget (`update_meter`). The needle is driven by a **smoothed** value with mechanical-meter ballistics (fast attack / slower decay) rather than the raw `rx->meter_db`. Strength is the per-receiver `rx->meter_smoothing` (0 = instant … 100 = max, default 50; slider in the receiver settings dialog, persisted); it scales the decay time constant (0…0.5 s, attack = decay/5), frame-rate independent via `rx->fps`. The needle state is seeded on first draw (no sweep from zero) and reseeded when the slider changes. The numeric dBm readout stays instantaneous.
- **`waterfall.c`, `rx_panadapter.c`, `tx_panadapter.c`** — Spectrum display rendering. `rx_panadapter.c` draws the passband/cursor and the green Shift+click TX-offset marker; gridline divisors handle zoom >8× via the `default` case. **`tx_panadapter.c` monitor span** is a fixed `TX_MONITOR_SPAN_HZ` (24 kHz, ±12, in `transmitter.h`) *not* derived from the protocol. `transmitter_init_analyzer()` **zooms the WDSP analyzer** onto that carrier-centred window via `span_clip_l/h` (clip the FFT bins outside the window) rather than analyzing the full `iq_output_rate` and cropping pixels afterwards — so the whole pixel budget lands *inside* the window and resolution is set by the in-window FFT bin count (`SPAN·fft_size/iq_rate`). `fft_size` is chosen adaptively (`8192 → 32768` cap) to reach ~1 bin per output pixel where feasible; `tx->pixels = panadapter_width` (one bin per column) and the draw maps them straight onto the columns with linear interpolation. This is the *only* way to beat the wideband resolution limit — the old full-span approach was capped by `dMAX_PIXELS` (16384), leaving ~100 bins in-window on HackRF. On P1/P2/fake the window is full per-pixel resolution; on wideband Soapy it's bin-limited (~409 at the 32768 cap, ~4× the old ~102) — raise `fft_size_cap` (buffers allow up to `WDSP_ANALYZER_MAX_SIZE`) to trade CPU/FFTW-planning for more. This tap (`analyzer_feed` of `iq_output_buffer`) is **post-DSP TX I/Q** — a clean modulated signal — so the span is only for context around the carrier; real PA IMD/linearity is not in this path (that's the PureSignal feedback ADC). On-screen detail is ultimately capped by `panadapter_width`; to see finer, narrow `TX_MONITOR_SPAN_HZ`.
- **`audio.c`** — Audio I/O (SoundIO on both platforms; ALSA/PulseAudio on Linux, CoreAudio on macOS). Includes the synthetic "System Default" output device (`AUDIO_SYSTEM_DEFAULT_NAME`), which new receivers use by default.
- **`midi2.c`, `midi3.c`** — MIDI learn and control mapping (platform-agnostic); `mac_midi.c` / `alsa_midi.c` for platform I/O.
- **`actions.c`** — Global action dispatch (used for keybindings and MIDI mappings).
- **`property.c`** — Persistence: save/load radio configuration to/from properties files (`~/.local/share/machpsdr/<device-mac>.props`; MIDI mappings in `midi.props`).
- **`waterfall_theme.c`** — Waterfall color theme definitions.
- **`gpu_image.c/h`** — **`GpuImage`, a reusable GTK4 GPU-composited image widget.** Subclasses `GtkWidget` and overrides `snapshot()` to draw a `GdkPixbuf` as a `GdkMemoryTexture` through the render-node pipeline (GPU), replacing the deprecated cairo pixbuf blit. Backs all raster surfaces: the RX/wideband/FT8 waterfalls and the SSTV/WEFAX image panels. Keeps the "draw reads the live pixbuf" flow via a pull `GpuImageSource` callback (existing `gtk_widget_queue_draw()` sites unchanged); per-widget fit mode (`GPU_FIT_STRETCH`/`LETTERBOX`/`WIDTH_BOTTOM`) + `GskScalingFilter`; an optional `GpuImageOverlay` (cairo overlay via `gtk_snapshot_append_cairo()`); and a `"resize"` signal (from `size_allocate`) re-implementing GtkDrawingArea's so pixbuf-reallocating resize callbacks need no edits. The texture is built from a **copy** of the pixbuf bytes (`g_bytes_new` → `gdk_memory_texture_new`) because a `GdkMemoryTexture`'s backing memory must stay immutable while the waterfall pixbufs mutate in place. This retired the last deprecation (`-Wno-deprecated-declarations` is gone from CFLAGS).
- **`hl2.c`** — Hermes-Lite 2 specific protocol extensions.
- **`wideband.c`, `wideband_panadapter.c`, `wideband_waterfall.c`** — Wideband spectrum display (separate from the per-receiver panadapter).
- **`ft8_decoder.c/h`** — FT8/FT4 receive decoder. No decoder runs by default; the operator picks one from the bottom-bar Decode block (`radio->decode_mode`, a `decode_mode_t` — `DECODE_OFF`/`FT8`/`FT4`/`SSTV`/`WEFAX`). The tap in `receiver.c:process_rx_buffer` feeds this module when the active RX is in a **digital mode (DIGU *or* DIGL)** and `decode_mode ∈ {FT8,FT4}` (the selector also keeps `radio->ft8_proto` in sync — 0=FT8/1=FT4, the source of truth for the TX/QSO/reporter path). Decimates 48 kHz demod audio to 12 kHz, buffers 15 s UTC slots, decodes in a background `GThread`. Uses the vendored `ft8_lib/` (Karlis Goba, MIT). Each `FT8_DECODE` carries structured `call_to`/`call_de`/`extra` fields (`ftx_message_decode_std`) for the QSO engine. **FT4:** protocol-aware via `ft8_decoder_set_protocol(ft4)` — shorter 7.5 s slot window/cadence/guard, `FTX_PROTOCOL_FT4`, and a protocol-parametric `measure_snr()` (real 4-GFSK WSJT-X-style dB). `ft8_decoder_get_spectrum()` exposes the 12 kHz audio ring for the FT8 waterfall.
- **`ft8_encoder.c/h`** — FT8/FT4 **TX engine**. `ft8_tx_prepare()` packs a message (`ftx_message_encode`) and synthesizes the GFSK waveform at 48 kHz (ported `gfsk_pulse`/`synth_gfsk`, parametric in `nsps`/`bt`/`n_sym`; shared `wave[]` sized to the longer FT8 waveform). Protocol-selected by `radio->ft8_proto` (FT8 ≈ 12.64 s / FT4 ≈ 5.04 s). A ~100 ms slot scheduler (`ft8_tx_arm`, GTK thread) keys MOX early in the chosen even/odd UTC slot (timed in wall-clock ms, `TX_SLOT_MS()` = 15000/7500) and drops it when the waveform ends. `ft8_tx_next_sample()` feeds `add_mic_sample()` in `transmitter.c`. **MOX safety watchdog:** `tx_tick` force-drops MOX if held longer than `wave_len` + `FT8_TX_MAX_MARGIN_MS` (2 s), preventing a stalled TX path from leaving MOX stuck on.
- **`ft8_qso.c/h`** — FT8 **auto-QSO state machine**. Polls the decoder every ~500 ms (GTK thread), drives the WSJT-X exchange (CQ → grid → report → R-report → RR73 → 73), keys TX on the opposite slot, and appends completed QSOs to `~/.local/share/machpsdr/ft8_log.adi` (ADIF, with `BAND` via `band_from_hz()`). `Enable Tx`/`Auto Seq` gates, manual `Tx1..Tx6` (`ft8_qso_select_tx`) and free text (`ft8_qso_send_free`), a 6-minute Tx watchdog. Station call/grid + TX offset/slot live on `RADIO`. **Worked/DXCC tracking:** `worked_load` reads the log and builds the worked-call set plus `worked_dxcc` (entity, any band) and `worked_dxcc_band` (per band); `ft8_qso_new_dxcc(call)` / `ft8_qso_new_dxcc_band(call, dial_hz)` back the panel's two-level "new one" highlight, `ft8_qso_country()` returns the cty.dat name. **Directed CQ:** `msg_cq` prepends `RADIO.ft8_cq_dir` (DX/EU/NA or 3-digit `nnn`; blank = plain CQ). **FT4:** exchange logic is protocol-agnostic; only `slot_even_from_utc()` and the ADIF `MODE` field are protocol-aware. Each QSO is also pushed to a network logger via `ft8_udp_log()`.
- **`ft8_udp.c/h`** — **Network QSO logging** (JTDX/WSJT-X compatible). `ft8_udp_log()` sends the completed QSO's ADIF record as a WSJT-X UDP "ADIF" message (magic `0xadbccbda`, schema 2, type 12) to `radio->ft8_log_udp_host`/`ft8_log_udp_port` (default `127.0.0.1:2237`) so QSOs appear in Log4OM/N1MM+/JTAlert/GridTracker. Gated by `radio->ft8_log_udp`.
- **`ft8_pskreporter.c/h`** — **PSK Reporter spot reporting.** `ft8_pskreporter_report()` (from `ft8_decoder.c:decode_slot`, once per slot) sends every decoded station to `report.pskreporter.info:4739` (UDP) in PSK Reporter's IPFIX format (enterprise number 30351; receiver-info + sender templates re-sent each packet). RF frequency = active RX dial + audio offset; `senderLocator` filled only when `extra` is a grid; free-text/self-spots skipped. **Gated by `radio->ft8_pskr` AND a non-empty `station_call` + `station_grid`.** Enabled via a checkbox in Configure → FT8. Compiled only with `FT8`.
- **`ft8_waterfall.c/h`** — **Dedicated FT8 band waterfall** (JTDX-style). Self-contained spectrogram of the FT8 audio passband: a windowed 4096-pt real FFT (`kiss_fftr`) of the decoder's 12 kHz ring via `ft8_decoder_get_spectrum()` → ~2.93 Hz/bin. Renders a scrolling `GdkPixbuf` (active RX's `waterfall_color_theme`) with a 500 Hz grid and a green TX-offset marker (base-tone line + a translucent band the width of the signal's occupied bandwidth, protocol-dependent from `ft8_proto`). **Independent of the WDSP analyzer** so it gives real per-Hz zoom the `pixels=width×zoom` panadapter can't. **Left-click sets the FT8 TX offset.** **Placement:** to the right of the active RX's RF spectrum (~1/3 width). The RF spectrum (`rx->vpaned`) is wrapped in a **windowless horizontal `GtkBox`** (`rx->wf_hpaned` — a box despite the name; a `GtkPaned` here blanks the main waterfall due to a nested-window quirk); `receiver_ft8_waterfall_sync()` packs/removes the waterfall as its second child. Shown only when the RX is in **DIGU and the FT8 panel is open**. Span follows the DIGU receive filter width, clamped 0.5–5 kHz. Own ~14 fps `g_timeout`.
- **`ft8_dxcc.c/h`** — **DXCC entity resolver.** Parses AD1C's `cty.dat` (bundled in repo root; ~346 entities) into exact-call + prefix hashes; `ft8_dxcc_entity(call)` returns an entity index by exact override else longest-prefix match (portable `SV9/DL1XX` handled by scanning `/`-segments). File located at runtime via `$MACHPSDR_CTY` → `.app` Resources → cwd → `~/.local/share/machpsdr/` → `/usr/local/share`. `ft8_dxcc_init()` is called from `main.c` **before** `ft8_qso_init()`. `ft8_dxcc_reload()`/`_count()`/`_path()` back the Reload cty.dat button in Configure → FT8. Missing file degrades gracefully. Compiled only with `FT8`.
- **`ft8_dialog.c/h`** — **FT8 configuration page** (`create_ft8_dialog`, the "FT8" page of the Configure dialog). Holds station **callsign** and **grid** (identity, not per-QSO — both force uppercase; **Enable Tx** in the panel is greyed until both are set), the DXCC status + Reload button, Network Logging settings, and the PSK Reporter toggle. Compiled only with `FT8`.
- **`ft8_panel.c/h`** — Embedded **FT8 QSO panel**, slotted into the RX stack in place of the second receiver. **Opt-in:** with an FT8/FT4 decoder selected in DIGU, the bottom-bar Decode block shows a compact decode readout and a "Show FT8 Panel" toggle (`ft8_expand_cb`); the panel appears only while `radio->ft8_panel_open`. `radio_ft8_panel_sync()` creates/tears it down from `ft8_panel_open && mode==DIGU && decode_mode∈{FT8,FT4}` and disables "Add Receiver" while it owns the slot. Layout: a config row (FT8/FT4 protocol selector → `RADIO.ft8_proto`; TX offset/slot; directed-CQ combo → `RADIO.ft8_cq_dir`), then a split with the Tx1–Tx6 message column (left) and the rolling band-activity list (right; CQ rows green, to-me rows bold, "CQ only" filter, double-click to work a station, two-level new-DXCC highlight gold/blue + country tooltip). The list is an **accumulating history** (append-only, capped at `MAX_ROWS`, never auto-cleared; `refresh()` appends a slot once keyed on the `disp_utc` label). **Erase** clears the list *and* re-stamps `disp_utc` so the decoder's retained last batch isn't re-appended. While the panel is open the bottom-bar block shows a QSO status readout. TX offset is also settable by **Shift+click** on the RX panadapter.
  - **Decoder selection (general practice — never offer a decoder the current mode can't run):** the bottom-bar Decode block carries a right-aligned decoder combo (`decode_sel` → `radio->decode_mode`), a **GtkListStore-backed `GtkComboBox`** whose visible rows are the decoders valid in the current RX mode. `decode_valid_mask(rx)` returns the allowed set (DIGU/DIGL = Off/FT8/FT4/SSTV/WEFAX; **FMN = Off + SSTV only** — FT8/FT4/WEFAX are HF-SSB-only, SSTV is the sole FM/ISS decoder); `decode_sel_sync(r)` rebuilds rows when that set changes and drops `decode_mode` to `DECODE_OFF` if the selection is no longer valid. Each row stores its enum in `DSEL_MODE` (read from the model, not the row index). The compact bottom-bar decode readout is Pango markup so "new one" callsigns get the same two-level DXCC colouring (gold/blue) as the panel, via font colour.
  - **Zoom hard limit:** WDSP's analyzer keeps fixed `dMAX_PIXELS` (16384) buffers and `rx->pixels == panadapter_width × zoom` is passed straight to `SetAnalyzer`; exceeding 16384 corrupts the heap (blank waterfall + broken RX/decode). So `receiver_change_zoom` and the panadapter `resize_timeout` clamp zoom to `16384 / panadapter_width` (effective max is width-dependent). Deep per-Hz FT8 viewing is provided by `ft8_waterfall.c` instead; a true 32× would need a span-based (`SetAnalyzer` fmin/fmax) rework.
- **`sstv_decoder.c/h`** — **SSTV image receive decoder** (Martin/Scottie/Robot/PD). Self-contained analogue-SSTV decoder, **no external DSP** (no WDSP/FFT). Tapped in `receiver.c:process_rx_buffer` on the 48 kHz demod audio when the RX is in **DIGU/DIGL** (HF over SSB) **or FMN** (VHF/ISS over narrow FM — the ISS transmits 145.800 MHz FM, so Robot 36/PD120 need FMN; the discriminator is amplitude-independent) and `decode_mode==DECODE_SSTV`. Pipeline: a **51-tap windowed Hilbert-FIR FM discriminator** → instantaneous frequency (1500 Hz black … 2300 Hz white, 1200 Hz sync); a **VIS-header detector** (1900 Hz leader → 1200 Hz start bit → 8×30 ms bits, parity-checked) auto-selects the mode; then a family-dispatched per-line decoder. **Families:** Martin M1/M2 + Scottie S1/S2/DX (direct GBR), Robot 36 (YUV 4:2:0, alternating R-Y/B-Y), Robot 72 (YUV 4:2:2), PD50/90/120/160/180/240 (YUV 4:2:0, two image rows per transmitted line). GBR sync placement differs by family. **Per-line sync locking** (`locate_sync`) re-anchors every line to cancel clock offset/slant; **line 0 is anchored on VIS timing, not searched**. A separate `tx_line` counter drives the sync prediction (PD emits two rows per line). **Two offset-tolerant start paths besides VIS** (both gate on the sync falling edge, so the VIS field is rejected): (a) forced-mode sync anchor — `sstv_decoder_set_mode(vis)` skips VIS and anchors on the first clean pulse; (b) automatic line-period detection (auto mode) — 5 consecutive syncs matched to the closest mode's line period. Both are the reliable path for **FM/VHF SSTV (ISS)**, where FMN de-emphasis smears the 30 ms VIS bits. **Auto-slant:** the per-line residual `sync − pred` drives a servo on `line_samples`/`clock_scale`, removing a sample-rate slant automatically (manual `Slant ±` is a fine ±20 ppm trim on top). **AFC:** `freq_offset` is seeded from the anchoring sync and tracked line-by-line; `freq2val()` and `locate_sync()` subtract it, tolerating ±200 Hz mistune / ISS Doppler; exposed via `sstv_decoder_get_afc()`. Image in a mutex-protected RGB buffer; `sstv_decoder_get_image()` returns a fresh `GdkPixbuf` copy. All decode runs inline on the RX audio thread (atomic no-op when disabled). Compiled only with `SSTV`.
- **`sstv_encoder.c/h`** — **SSTV image TX encoder** (mirror of the decoder). Encodes a `GdkPixbuf` (fitted by `letterbox()` — aspect-preserving, not stretched) into an analogue-SSTV tone timeline: a standard VIS header (the exact inverse of `decode_vis()`) then per-line sync/porch/separator tones and FM-encoded pixel scans (`val2freq`: 1500 Hz black … 2300 Hz white). Same timings as the decoder, renamed `TX_MODES[]` here (because `mode.h`, included for `DIGU`/`DIGL`/`FMN`, defines a `MODES` enum). Five family builders mirror the decoder (`build_gbr`/`build_robot36`/`build_robot72`/`build_pd`); RGB→YCbCr is full-range BT.601 (the inverse of the decoder). **Playback:** `sstv_tx_prepare` builds the `{freq,dur_ms}` timeline (GTK thread); `sstv_tx_next_sample()` walks it with a phase accumulator, deciding boundaries from a **cumulative double sample count** (`seg_end_smp`) so fractional per-pixel durations never accumulate rounding drift. A raised-cosine envelope suppresses key clicks. **TX integration:** `add_mic_sample()` substitutes `sstv_tx_next_sample()` whenever `sstv_tx_active()` (any phone mode — DIGU/DIGL as SSB, FMN as FM). `sstv_tx_start()` validates `can_transmit` + mode ∈ {DIGU,DIGL,FMN}, keys MOX, and runs a ~100 ms tick that drops MOX at waveform end with a safety watchdog (`total_ms + SSTV_TX_MARGIN_MS`). Self-contained. Note: the decoder's *forced-mode* sync anchor false-triggers on the VIS break, so a same-app round-trip should use **Auto (VIS)** decode. Compiled only with `SSTV`.
- **`sstv_panel.c/h`** — Embedded **SSTV image panel**, slotted into the RX stack in place of the second receiver. Shows the incoming image (scaled to fit, nearest-neighbour, letterboxed 4:3), a status/progress line, a **Mode** override combo (Auto + all modes → `sstv_decoder_set_mode`), **Slant ±** trim, and **Save** (PNG to `~/.local/share/machpsdr/sstv/`) / **Clear**. **Tx row:** a concrete-mode combo, **Load…** (any `gdk_pixbuf` image, previewed while idle), a **Send/Stop** toggle (`sstv_tx_prepare` + `sstv_tx_start`) and a `GtkProgressBar`; Send is greyed until an image is loaded, an in-flight TX is stopped on `destroy`. Own ~5 fps `g_timeout`. Opened via the bottom-bar "Show SSTV" toggle (`sstv_expand_cb` → `radio->sstv_panel_open`); `radio_sstv_panel_sync()` gates it on `sstv_panel_open && mode∈{DIGU,DIGL} && decode_mode==DECODE_SSTV` and it is mutually exclusive with the FT8/WEFAX panels over the second-RX slot.
- **`wefax_decoder.c/h`** — **WEFAX / HF-radiofax RX decoder** (the shortwave cousin of the SSTV decoder; weather charts on HF, received in DIGU/DIGL). Reuses the SSTV tone convention (1500 Hz black … 2300 Hz white) and the same 51-tap Hilbert-FIR discriminator → inst-freq ring, but the format is a **continuous scan** (no fixed frame height — the image grows in a scrolling `BUF_H` buffer) with **no VIS header**. Line sync comes from the transmission's own signals: an **automatic start-tone detector** (300 Hz for IOC 576 / 675 Hz for IOC 288) begins a fresh page (`begin_page()`, sets IOC and seeds AFC), then **continuous auto-phasing** (`p_autophase`, default on) self-aligns the picture — it EMAs per-column edge energy (`col_energy[IMG_W]`) so a recurring vertical feature (margin/border) builds a peak, and after ~24 lines applies a **single** shift to bring that peak to the left edge and **freezes** (`phase_locked`); the one-time acquire is deliberate — a per-line phase correction is itself a slant. Line period from **LPM** (`SR*60/lpm`; 60/90/120/240), each line resampled to `IMG_W` = **1810** ≈ the native IOC576 element count (576·π), so thin chart lines resolve ~1 element/pixel (rendering narrower greyed them out — needs a **wide ~1.9 kHz DIGU filter** upstream or transitions smear). **Quality helpers (default on):** one-time white-anchored AFC (a chart is mostly white → anchor the dominant frequency over the first ~24 lines to 2300 Hz once, then freeze; the start-tone path seeds it itself); conditional-median despeckle (`p_denoise`, replaces only isolated impulse spikes, leaving edges/thin lines). Free-runs continuously once enabled. API mirrors the SSTV decoder (`wefax_decoder_set_enabled/add_audio/set_lpm/set_ioc/set_autostart/start/reset/adjust_slant/get_afc/get_status/get_image`). Tapped alongside the SSTV tap (HF USB only). Self-contained, RX only (no TX). Compiled only with `SSTV`.
- **`wefax_panel.c/h`** — Embedded **WEFAX image panel** (mirrors `sstv_panel.c`). A `GtkDrawingArea` shows the tall scrolling image fit-to-width, **bottom-anchored**; clicking sets the left margin (`wefax_decoder_nudge_phase`). Toolbar: **LPM** & **IOC** combos, **Auto-start**/**Auto-phase**/**Denoise** checkboxes (default on), **Invert** (default off, applied at `get_image`), a manual **Start**, **Slant ±**, **Save** (PNG to `~/.local/share/machpsdr/wefax/`) and **Clear**. All settings read from / written back to `RADIO` (`wefax_lpm`/`ioc`/`autostart`/`autophase`/`denoise`/`invert`, persisted). Own ~3 fps `g_timeout`. Opened via the bottom-bar "Show WEFAX" toggle (`wefax_expand_cb`); `radio_wefax_panel_sync()` gates it on `wefax_panel_open && mode∈{DIGU,DIGL} && decode_mode==DECODE_WEFAX`, mutually exclusive with the FT8/SSTV panels.
- **`subrx.c`** — Sub-receiver support: a second WDSP demod channel (`rx->channel + SUBRX_BASE_CHANNEL`) on the same off-air I/Q, with its own VFO-B freq/mode/filter/AGC. Toggled by the **SUBRX** button (`vfo.c`). Audio: `process_rx_buffer()` puts main on the left / sub on the right with an adjustable crossfeed — `rx->subrx_mix` (0 = hard L/R split … 100 = equal mono blend, read live per buffer). Both `subrx_enable` and `subrx_mix` are **persisted** per receiver; because `frequency_changed()`/`process_rx_buffer()` dereference `rx->subrx` whenever `subrx_enable` is set, the restored "on" state is parked in `rx->subrx_restore_pending` and only applied (via `create_subrx()` + `subrx_enable=TRUE`) at the **end** of `create_receiver`, after the main WDSP channel is open — restoring it earlier would NULL-deref the not-yet-created sub-channel. Mix slider in the receiver settings dialog (`receiver_dialog.c`, RX audio group).
- **`diversity_mixer.c` / `diversity_dialog.c`** — Diversity reception (combine two coherent ADC streams to null interference / fight fading). Wired via the VFO **DIV** button (`add_diversity_mixer` → WDSP `create_divEXT`), mixed in `add_iq_samples`, gain/phase controls in **Configure → Diversity**. **Protocol 1 only and unverified on hardware in this fork** (like PureSignal) — the dialog carries a PureSignal-style disclaimer; needs a radio with two receivers/ADCs to test.
- **`recorder.c/h`** — **I/Q + demodulated-audio recorder.** A global singleton (own `GMutex`) that, when armed for a receiver, streams two 16-bit stereo WAVs into `~/.local/share/machpsdr/`: `rec_<UTC>_iq.wav` (off-air I/Q at `rx->sample_rate`, tapped in `full_rx_buffer`/`full_diviqrx_buffer` **before** the noise blanker — genuine off-air I/Q in the same format `--faker` reads, hence loop-back-able) and `rec_<UTC>_af.wav` (demodulated audio at 48 kHz, tapped at the end of `process_rx_buffer` **before** the software listen volume). Minimal streaming RIFF/WAVE writer (header patched with real sizes on stop). Taps run on the RX audio thread and fast-reject buffers not belonging to the recording receiver; `recorder_toggle` (GTK thread) starts/stops from the bottom-bar **SETUP** Record/Stop button. **Settings** in Configure → Recording (`create_recording_dialog`): output folder + which streams to write (`rec_iq`/`rec_af`/`rec_dir`, persisted, read when a recording starts). *(Known limit: WAV size fields are 32-bit → headers overflow past ~44 min @384k; data still written.)*
- **`ext.c`** — Thread-safe UI dispatch helpers (`ext_*` functions wrap `g_idle_add()`).
- **`log.c/h`** — **Levelled console logging.** Three levels `ERROR < INFO < DEBUG`; macros `log_error()`/`log_info()`/`log_debug()` write to **stderr**, mutex-serialised (safe from any thread) and level-prefixed. The level guard lives in the macro (a single int compare against `machpsdr_log_level`), so a `log_debug()` on a hot path costs nothing and its args aren't evaluated when DEBUG is off. Threshold defaults to **INFO**, set at start-up in `main.c` from `MACHPSDR_LOG=error|info|debug` then overridden by the CLI (`--log-level <lvl>`, `--debug`/`-v`/`--verbose`, `--quiet`/`-q`). **New code should use the `log_*` macros, not bare `printf`/`g_print`** (the vendored `ft8_lib/` and `wdsp/` trees are left untouched).

### UI Dialogs
All dialogs follow the `*_dialog.c/h` naming convention: `radio_dialog`, `receiver_dialog`, `transmitter_dialog`, `midi_dialog`, `configure_dialog`, `bookmark_dialog`, `diversity_dialog`, `pa_dialog`, `eer_dialog`, `puresignal_dialog`, etc.

### Threading
Background tasks (protocol I/O, wisdom file creation) use `GThread`. UI updates must be dispatched to the GTK main thread via `g_idle_add()` or the `ext_*` wrappers in `ext.c` — never call GTK functions directly from protocol/audio threads.
