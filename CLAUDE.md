# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MacHPSDR is a GTK3-based SDR (Software Defined Radio) control application for HPSDR hardware, written in C. It is a personal fork of [LinHPSDR](https://github.com/g0orx/linhpsdr) by John Melton (G0ORX/N6LYT), with a primary focus on macOS compatibility and several feature additions (freetune mode, waterfall themes, ppm correction, att10/att20 filter control, etc.). Licensed under the GNU GPL (v2 or later); see `LICENSE` and `NOTICE`.

The binary, install paths and config directory use the lowercase name `machpsdr`; the display name (window title, About dialog, `.app` bundle) is `MacHPSDR`.

## Build Commands

```bash
# Build the binary
make

# Install to /usr/local/bin
sudo make install        # Linux
make install             # macOS

# Clean build artifacts
make clean

# Build self-contained macOS .app bundle (requires dylibbundler)
make app
open MacHPSDR.app
```

No automated test suite exists — testing is manual with physical hardware. For
hardware-free smoke testing there is a synthetic **fake device**: run
`./machpsdr --faker <iq.wav>` (e.g. `--faker ft8.wav`) to loop an I/Q recording
through the full RX/decoder chain. With `--faker` the device-selection dialog is
skipped and the fake radio starts straight up, so it can be launched headless
(e.g. under lldb). See `fake_protocol.c` and the flag parsing in `main.c`.

## Dependencies

### macOS (via Homebrew)
```bash
brew install fftw gtk+3 gnome-icon-theme libsoundio libffi soapysdr dylibbundler
```

### Linux (via apt)
```bash
sudo apt-get install libfftw3-dev libpulse-dev libsoundio-dev libasound2-dev libgtk-3-dev libsoapysdr-dev
```

### WDSP (vendored — do NOT install upstream)
The patched WDSP this fork needs is vendored in-tree under `wdsp/` and is built
automatically by `make` on **both platforms** (`wdsp/libwdsp.dylib` on macOS,
`wdsp/libwdsp.so` on Linux); the binary finds it via rpath (`@loader_path/wdsp`
on macOS, `$ORIGIN/wdsp` on Linux). Do **not** `git clone g0orx/wdsp` and
`sudo make install` it — a stock system `-lwdsp` compiles but silently breaks
this fork's WFM demod and other DSP patches. The Makefile's `wdsp-local` target
(`$(MAKE) -C wdsp`) is an order-only prereq of the main binary on both platforms.

## Platform Differences

- **macOS**: Uses `audio.c` (SoundIO + CoreAudio) for audio, `mac_midi.c` for MIDI (CoreMIDI framework), no CWDAEMON support
- **Linux**: Uses `audio.c` with ALSA/PulseAudio/SoundIO, `alsa_midi.c` for MIDI, CWDAEMON enabled by default

> Note: `audio.c` is the audio backend on **both** platforms. The Makefile's `AUDIO_SOURCES=portaudio.c` (Darwin) is a dead variable — `portaudio.c` does not exist and is never compiled; `audio.c` is hardcoded in `SOURCES`/`OBJS`.

Platform is detected via `uname -s` in the Makefile (`Darwin` vs `Linux`).

## Build Feature Flags (Makefile)

| Flag | Default | Notes |
|------|---------|-------|
| `SOAPYSDR` | enabled | RTL-SDR/LimeSDR/HackRF support (RX; HackRF TX implemented, half-duplex, untested on hardware) |
| `MIDI` | enabled | MIDI controller support |
| `CWDAEMON` | enabled (Linux only) | CW keying via unixcw |
| `PURESIGNAL` | disabled | Adaptive distortion correction (Protocol 1 only) |
| `OPENGL` | disabled | OpenGL rendering |
| `FT8` | enabled | FT8 RX decoder + TX/auto-QSO (decoder auto-enabled in DIGU; big QSO panel is opt-in via a bottom-bar toggle); vendored `ft8_lib/` |
| `SSTV` | enabled | SSTV image RX decoder (Martin/Scottie/Robot/PD, incl. ISS Robot 36 & PD120) + embedded image panel; self-contained (no external DSP) |

To toggle, comment/uncomment the `*_INCLUDE=*` lines near the top of the Makefile.

## Architecture

### Application State
The global `RADIO *radio` struct (`radio.h`) is the central application state. It holds references to up to 8 `RECEIVER` structs, one `TRANSMITTER` struct, and hardware/protocol configuration.

### Key Modules

- **`main.c`** — Entry point, GTK init, device discovery, main window creation
- **`radio.c/h`** — Radio lifecycle management, hardware model definitions (ANAN, Hermes, Hermes-Lite, Orion, Atlas, etc.)
- **`receiver.c/h`** — Per-receiver state: VFO A/B, AGC, NR/NB/ANF, filters, modes, panadapter/waterfall. **Analyzer-feed heap-safety invariant:** WDSP's `Spectrum0()` writes each transfer block into a fixed I/Q input ring (`XCreateAnalyzer` `max_size` × `dSAMP_BUFF_MULT`(2) = `WDSP_ANALYZER_MAX_SIZE`×2 = 2¹⁹ complex samples) and only wraps its write index at the ring end, so **the transfer block must divide the ring exactly** (`// REQUIRES buff_size IS A SUB-MULTIPLE…` in `wdsp/analyzer.c`) — otherwise the last block before the wrap runs off the buffer and corrupts the heap (intermittent, ASLR-dependent crash ≈ every ring cycle). The wideband RX block (5120 = 2¹⁰·5) and the widest TX block (40960 at the 1920 kHz span) do **not** divide 2¹⁹, so the panadapter feed goes through `analyzer_feed()` (`receiver.c`), which splits any buffer into `ANALYZER_FEED_BLOCK` (1024 = gcd(5120,2¹⁹)) sub-blocks; `SetAnalyzer` is configured with `bf_sz == ANALYZER_FEED_BLOCK` to match. A `_Static_assert` in `receiver.h` enforces the divisibility at compile time. `bpsk.c` (2048) and `wideband.c` (16384) already use ring-dividing blocks and are unaffected.
- **`transmitter.c/h`** — TX path: filtering, CTCSS, EER, PureSignal, metering. The TX panadapter feed uses `analyzer_feed()` (see `receiver.c/h`) for the same input-ring heap-safety reason — the 1920 kHz span's 40960-sample output block does not divide WDSP's 2¹⁹ analyzer ring.
- **`protocol1.c`, `protocol2.c`, `soapy_protocol.c`** — Hardware communication for Classic HPSDR, enhanced protocol, and SoapySDR devices respectively. **PPM correction** (`radio->ppm_correction_value`, a **`double`**, ±500 ppm — fractional for sub-ppm resolution, which matters on the high bands) is applied in the RX/TX tune-frequency computation of **all three** protocols via the shared `radio_ppm_correction(f_rf)` helper (`radio.c`; returns `llround(f_rf*ppm/1e6)`, full floating precision, `f_rf` = dial−LO). Protocol 1 reads it live in its output thread; Protocol 2 / SoapySDR pick up a changed ppm on the next `frequency_changed()` retune. (Persisted as `%f`; older integer-valued props load fine via `atof`.)
- **`ppm_cal.c/h`** — **PPM (oscillator) calibration against time-signal stations.** Holds the reference-station table (`PPM_STATION` name+carrier Hz — RWM/WWV/CHU/BPM on HF, MSF/DCF77/Droitwich on LF) with `ppm_station_count()`/`ppm_station(i)` accessors, and `ppm_cal_tune_to_station()` (parks the active RX on the carrier in CW-USB for zero-beating by ear). Selected station persisted in `radio->ppm_ref_station`. **Automatic measurement:** `ppm_cal_measure_start()` retunes the active RX so the carrier lands at a fixed audio offset (`PPM_MEAS_OFFSET` 1500 Hz, clear of the DC spike), then `ppm_cal_iq_feed()` — a tap in `receiver.c:full_rx_buffer`/`full_diviqrx_buffer` on the **raw off-air I/Q** (demod-independent) — accumulates `PPM_FFT_N`(32768)-pt frames, runs a **self-contained radix-2 FFT** (no FT8/kiss/fftw dependency), finds the carrier bin, parabolic-interpolates to sub-bin (~0.1 Hz), and averages `PPM_FRAMES`(6) frames against ionospheric Doppler (skipping `PPM_SETTLE` after retune, SNR-gated). Closed-loop correction `ppm_new = ppm_old + (residual_Hz/(carrier−lo))·1e6` where `residual = measured − PPM_MEAS_OFFSET`; sign follows the HPSDR non-inverted I/Q convention (`iq[2k]=I`, `[2k+1]=Q`, above-LO ⇒ +baseband) — re-running shows the residual collapse toward 0. Runs on the RX audio thread (atomic fast-path no-op when idle); the UI polls `ppm_cal_measure_poll()`. The RX's VFO frequency/mode/filter are saved at start and restored by `ppm_cal_restore_rx()` when the run ends (so the radio is not left parked on the reference station). UI in the **Configure → Misc** page (`labels_dialog.c`, "Frequency Calibration (PPM)" frame): ppm spinner (0.01 steps) + station combo + **Calibrate** & **Tune** buttons + status/result readouts. The **Calibrate** button doubles as **Stop** while running (`ppm_cal_measure_cancel()`); the ~150 ms GTK poll shows per-frame progress (`N/6`), auto-applies the result to the spinner on success, restores the RX, and is torn down on the page's `destroy`.
- **`discovery.c`, `protocol1_discovery.c`, `protocol2_discovery.c`, `soapy_discovery.c`** — Network device discovery
- **`vfo.c`** — Frequency display and VFO control widget
- **`waterfall.c`, `rx_panadapter.c`, `tx_panadapter.c`** — Spectrum display rendering
- **`audio.c`** — Audio I/O (SoundIO on both platforms; ALSA/PulseAudio on Linux, CoreAudio on macOS). Includes the synthetic "System Default" output device (`AUDIO_SYSTEM_DEFAULT_NAME`), which new receivers use by default
- **`midi2.c`, `midi3.c`** — MIDI learn and control mapping (platform-agnostic); `mac_midi.c` / `alsa_midi.c` for platform I/O
- **`actions.c`** — Global action dispatch (used for keybindings and MIDI mappings)
- **`property.c`** — Persistence: save/load radio configuration to/from properties files (`~/.local/share/machpsdr/<device-mac>.props`; MIDI mappings in `midi.props`)
- **`waterfall_theme.c`** — Waterfall color theme definitions
- **`hl2.c`** — Hermes-Lite 2 specific protocol extensions
- **`wideband.c`, `wideband_panadapter.c`, `wideband_waterfall.c`** — Wideband spectrum display (separate from per-receiver panadapter)
- **`ft8_decoder.c/h`** — FT8 receive decoder. **Decoder selection:** no decoder runs by default; the operator picks one from the bottom-bar Decode block (`radio->decode_mode`, a `decode_mode_t` — `DECODE_OFF`/`FT8`/`FT4`/`SSTV` — the single source of truth for *which* decoder taps the active RX's audio, persisted). The tap in `receiver.c:process_rx_buffer` feeds the FT8 decoder while the active RX is in a **digital mode (DIGU *or* DIGL)** *and* `decode_mode` is `DECODE_FT8`/`DECODE_FT4` (the selector also keeps `radio->ft8_proto` in sync — 0/1 — for the TX/QSO/reporter path). `DECODE_SSTV` routes to the separate `sstv_decoder.c` (below), not this module. It decimates the 48 kHz demod audio to 12 kHz, buffers 15-second UTC slots, decodes in a background `GThread`. Displayed in the bottom-bar decoder block (see `rds_update_cb` in `radio.c`). Uses the vendored `ft8_lib/` (Karlis Goba, MIT); gated by the `FT8` Makefile flag. **Decodes independently of the listening volume/mute:** when a decoder is tapping the RX (see `decoder_taps_audio()` in `receiver.c`) the WDSP audio-panel gain is forced to unity (`rx_panel_gain()`) so the decoder tap (`rx->audio_output_buffer`) always gets a full-level signal, and the volume/mute is applied to the audible output in software in `process_rx_buffer()` — the operator does not listen to FT8. (With no decoder selected, DIGU/DIGL behave as normal listening modes — no unity-gain override.) Each `FT8_DECODE` also carries structured `call_to`/`call_de`/`extra` fields (via `ftx_message_decode_std`) for the QSO engine. **FT4 support:** the decoder is protocol-aware via `ft8_decoder_set_protocol(ft4)` (called each RX buffer from `receiver.c`, derived from `decode_mode`; `radio->ft8_proto` remains the source of truth read by the encoder/QSO/reporters — 0=FT8, 1=FT4). In FT4 the decode window (`slot_samples()`), decode cadence (`decode_hop()`) and minimum-audio guard (`mon_min_samples()`) are the shorter 7.5 s-slot values, the `monitor_config_t` protocol is `FTX_PROTOCOL_FT4`, and `measure_snr()` is **protocol-parametric** (n_sym / n_tones / symbol_period) so FT4 gets a real 4-GFSK WSJT-X-style SNR (reference term `10log10(2500/tone_hz)` = 20.79 dB for FT4's 20.833 Hz tone spacing, vs 26.02 dB for FT8) — AWGN-calibrated to ~±1 dB. The slot-boundary label (`work_slot_time`) is computed in ms and **rounded** to the nearest second so FT4's half-second (7.5 s) boundaries map back to the correct slot index in `slot_even_from_utc()`. `SLOT_SAMPLES`/`RING_CAP` stay sized for the longer FT8 window (FT4 fits inside).
- **`ft8_encoder.c/h`** — FT8/FT4 **TX engine** (Phase 2). `ft8_tx_prepare()` packs a message (`ftx_message_encode`) and synthesizes the GFSK waveform at the 48 kHz mic rate (ported `gfsk_pulse`/`synth_gfsk`). Protocol-selected by `radio->ft8_proto`: **FT8** = `ft8_encode`, BT=2.0, 79 symbols ≈ 12.64 s (7680 samp/sym); **FT4** = `ft4_encode`, BT=1.0, 105 symbols ≈ 5.04 s (2304 samp/sym) — `synth_gfsk` is parametric (`nsps`, `bt`, `n_sym`), the shared `wave[]` buffer is sized to the longer FT8 waveform. A ~100 ms slot scheduler (`ft8_tx_arm`, GTK thread) keys MOX (`set_mox`) early in the chosen even/odd UTC slot and drops it when the waveform ends. Timing is done in **wall-clock milliseconds** (`g_get_real_time`) with a protocol slot length `TX_SLOT_MS()` (15000/7500) so FT4's half-second boundaries are honoured. `add_mic_sample()` in `transmitter.c` substitutes `ft8_tx_next_sample()` for the mic input in DIGU while `ft8_tx_active()`, so the normal DIGU (USB) TX chain modulates the tone to dial+offset (universal across protocol1/2/soapy). **MOX safety watchdog:** `tx_tick` stamps `key_time_ms` when it raises MOX and force-drops it if MOX has been held longer than the actual waveform length + `FT8_TX_MAX_MARGIN_MS` (2 s) — derived from `wave_len` so it adapts to FT8 vs FT4 — preventing a stalled TX path (`tx_idx` never reaching `wave_len`) from leaving MOX stuck on.
- **`ft8_qso.c/h`** — FT8 **auto-QSO state machine** (Phase 2). Polls the decoder every ~500 ms (GTK thread), drives the standard WSJT-X exchange (CQ → grid → report → R-report → RR73 → 73), keys TX on the opposite slot, and appends completed QSOs to `~/.local/share/machpsdr/ft8_log.adi` (ADIF). Also: `Enable Tx`/`Auto Seq` gates, manual `Tx1..Tx6` (`ft8_qso_select_tx`) and free text (`ft8_qso_send_free`), worked-before lookup from the ADIF log (`ft8_qso_worked`), and a 6-minute Tx watchdog. Station call/grid + TX offset/slot live on `RADIO` (`station_call`, `station_grid`, `ft8_tx_offset`, `ft8_tx_even`), persisted in `radio_save_state`. Each completed QSO is also pushed to a network logger via `ft8_udp_log()` (see `ft8_udp.c`). **Logbook / worked tracking:** `log_qso` writes an ADIF `BAND` field (in addition to `FREQ`), derived from the dial via `band_from_hz()`. On start-up `worked_load` reads the log one record per line (`adif_get`) and, besides the worked-call set (`worked`), builds two DXCC sets: `worked_dxcc` (entity worked on **any** band) and `worked_dxcc_band` (key `band*1000+ent`, per-band); older records with only `FREQ` still get a band. `ft8_qso_new_dxcc(call)` = new entity ever, `ft8_qso_new_dxcc_band(call, dial_hz)` = new on that band — both back the panel's two-level "new one" highlight. `ft8_qso_country()` returns the cty.dat country name. **Directed CQ:** `msg_cq` (and the Tx6 message) prepend an optional modifier from `RADIO.ft8_cq_dir` → `CQ <dir> CALL GRID` (region like DX/EU/NA or a 3-digit `nnn`, per the FT8 `CQ a[bcd]`/`CQ nnn` codec support); blank = plain CQ. Set from the panel's config-row combo; persisted in `radio_save_state`. **FT4:** the exchange logic (identical 77-bit payloads) is protocol-agnostic; only `slot_even_from_utc()` (slot = seconds-of-day×2/15 for FT4's 7.5 s slots) and the ADIF `MODE` field (`FT4`/`FT8` from `radio->ft8_proto`) are protocol-aware. The `MODE` propagates to the network logger automatically (`ft8_udp_log` forwards the record verbatim).
- **`ft8_udp.c/h`** — **Network QSO logging** (JTDX/WSJT-X compatible). `ft8_udp_log()` sends the completed QSO's ADIF record as a WSJT-X UDP "ADIF" message (magic `0xadbccbda`, schema 2, message type 12; big-endian, uint32-length + UTF-8 strings) to a configurable host:port, so QSOs appear in a logger (Log4OM, N1MM+, JTAlert, GridTracker) over the network. Gated by `radio->ft8_log_udp`; host/port in `radio->ft8_log_udp_host`/`ft8_log_udp_port` (default `127.0.0.1:2237`), all persisted in `radio_save_state`.
- **`ft8_pskreporter.c/h`** — **PSK Reporter spot reporting.** `ft8_pskreporter_report()` is called from the decoder worker (`ft8_decoder.c:decode_slot`) once per 15 s slot and sends every decoded station as a reception report to `report.pskreporter.info:4739` (UDP), the same network WSJT-X/JTDX feed — so the operator's spots appear on the PSK Reporter map. Wire format is PSK Reporter's IPFIX protocol (private enterprise number 30351): a message header, a receiver-information options template (`0x50E2`: receiverCallsign/Locator/decodingSoftware/antennaInformation) and a sender/reception-record template (`0x50E3`: senderCallsign/frequency(5B)/sNR(1B)/mode/senderLocator/informationSource(1B)/dateTimeSeconds), both re-sent each packet, followed by the receiver data record and one sender record per spot. RF frequency = the active RX dial (`frequency_a`) + the decode's audio offset; `senderLocator` is filled only when the decode's `extra` is a Maidenhead grid; free-text/telemetry decodes (no `call_de`) and self-spots are skipped. **Gated by `radio->ft8_pskr` AND a non-empty `station_call` + `station_grid`** (per the user requirement — nothing is sent until both identity fields are set). Enabled via a checkbox in Configure → FT8 (`ft8_dialog.c`); `ft8_pskr` persisted in `radio_save_state`. Packet layout byte-verified with an IPFIX round-trip parser. The reported `mode` string follows `radio->ft8_proto` (`FT4`/`FT8`). Compiled only with the `FT8` flag.
- **`ft8_waterfall.c/h`** — **Dedicated FT8 band waterfall** (JTDX-style). Self-contained spectrogram of just the FT8 audio passband (0–3000 Hz): a windowed 4096-pt real FFT (`kiss_fftr`) of the decoder's 12 kHz audio ring via `ft8_decoder_get_spectrum()` (in `ft8_decoder.c`) → ~2.93 Hz/bin, fine enough to separate FT8 tones. Renders a scrolling `GdkPixbuf` coloured with `get_waterfall_color()` (the active RX's `waterfall_color_theme`), with a 500 Hz frequency grid and a green TX-offset marker. The marker is a base-tone line plus a **translucent band spanning the signal's occupied bandwidth**, which is protocol-dependent (FT8 = 8 tones × 6.25 Hz ≈ 50 Hz; FT4 = 4 tones × 20.83 Hz ≈ 83 Hz, from `radio->ft8_proto`) so picking a clear TX slot is honest for FT4's wider footprint; the label reads `TX`/`FT4`. **Independent of the main WDSP analyzer** (no `SetAnalyzer`/`dMAX_PIXELS` limit), so it gives real per-Hz zoom the `pixels=width×zoom` main panadapter can't. **Left-click sets the FT8 TX offset** directly on a clear frequency. Its own ~14 fps `g_timeout`, torn down on `destroy`. **Placement:** to the **right of the active receiver's RF spectrum (~1/3 width)**. The RF spectrum (`rx->vpaned`) is wrapped in a **windowless horizontal `GtkBox`** (`rx->wf_hpaned` — a box, despite the name); `receiver_ft8_waterfall_sync()` (`receiver.c`) packs/removes the FT8 waterfall as its second child, sized to 1/3 of the row by an `ft8_wf_box_alloc` size-allocate handler that tracks resizes. A `GtkBox` is used deliberately, **not** a `GtkPaned`: wrapping `vpaned` in a `GtkPaned` blanked the main waterfall (window-hierarchy quirk), whereas the windowless box leaves the vpaned's `GdkWindow` parenting unchanged. Shown only when the RX is in **DIGU *and* the FT8 panel is open** (`radio->ft8_panel_open`) — hooked from `receiver_mode_changed`, `radio_ft8_panel_sync`, and once after `create_visual`. **Span:** follows the DIGU receive filter width (`filter_low_a/high_a`), clamped to 0.5–5 kHz (`wf_span_hz`); `ft8_decoder_get_spectrum` returns up to 5 kHz and the widget shows the filter sub-span, rescaling its content to any width on resize. The old main-panadapter FT8 auto-zoom was removed (this waterfall replaces it).
- **`ft8_dxcc.c/h`** — **DXCC entity resolver** (backs the "new one" highlight). Parses AD1C's `cty.dat` country file (bundled in the repo root; ~346 entities) into an exact-callsign hash plus a prefix hash, and `ft8_dxcc_entity(call)` returns a DXCC entity index by exact-call override else **longest-prefix** match (faithfully reproducing cty.dat precedence — e.g. `UA9X…`→European Russia via the 4-char district prefix while bare `UA9`→Asiatic Russia; portable `SV9/DL1XX` handled by scanning `/`-segments). File is located at runtime via `$MACHPSDR_CTY` → `.app` `../Resources/cty.dat` → cwd `cty.dat` → `~/.local/share/machpsdr/` → `/usr/local/share`. `ft8_dxcc_init()` is called from `main.c` **before** `ft8_qso_init()` so the log's worked-before scan can tag worked entities. `ft8_dxcc_reload()`/`_count()`/`_path()` back the **Reload cty.dat** button + status label in Configure → FT8. Missing file degrades gracefully (no highlight, no crash). Compiled only with the `FT8` flag. SNR reporting is unrelated. — Worked-DXCC tracking lives in `ft8_qso.c`: a `worked_dxcc` set (entity indices) built alongside the worked-call set in `worked_load`/`worked_add`; `ft8_qso_new_dxcc(call)` = entity resolvable AND not yet worked, `ft8_qso_country(call)` returns the country name. The panel (`ft8_panel.c`) highlights new-DXCC rows with a **two-level** `cell-background` driven by model columns `COL_BG`/`COL_BGSET`: **gold** (`#b8860b`) for a brand-new entity (any band, `ft8_qso_new_dxcc`) and **blue** (`#2f6fb0`) for one worked elsewhere but new on the current band (`ft8_qso_new_dxcc_band`, band taken from the active RX dial); it also shows the country as a hover tooltip (`COL_COUNTRY`, `on_query_tooltip`).
- **`ft8_dialog.c/h`** — **FT8 configuration page** (`create_ft8_dialog`, added to the Configure dialog as the **"FT8"** page). Holds the station **callsign** and **grid** (moved here from the panel — they are identity, not per-QSO controls; both entries force **uppercase** as you type, and **Enable Tx** in the panel is greyed out until both are set), the **DXCC** country-file status + Reload button (see `ft8_dxcc.c`), the **Network Logging** settings (enable, host/IP, port), and the PSK Reporter **Spot Reporting** toggle. Compiled only with the `FT8` flag.
- **`ft8_panel.c/h`** — Embedded **FT8 QSO panel** (Phase 2). A GtkWidget slotted into the RX stack *in place of the second receiver*. It is **opt-in**, not automatic: with an **FT8/FT4** decoder selected in DIGU the bottom-bar decode block shows a compact decode readout and a **"Show FT8 Panel"** toggle button (in the Decode block, right-aligned with the decoder selector, wired via `ft8_expand_cb`) opens the panel; it appears only while `radio->ft8_panel_open` is set. `radio_ft8_panel_sync()` (in `radio.c`, hooked from `receiver_mode_changed`) creates/tears down the panel from `ft8_panel_open && mode==DIGU && decode_mode∈{FT8,FT4}`, disables "Add Receiver" while it owns the slot, and force-closes it on leaving DIGU or switching away from an FT8/FT4 decoder. **Bottom-bar decoder selector:** the Decode block (`radio.c:rds_update_cb` / `create_visual`) carries a right-aligned `Off/FT8/FT4/SSTV` combo (`decode_sel`, `decode_sel_changed` → `radio->decode_mode`), shown in DIGU/DIGL; the FT8 Panel toggle sits below it and is shown only in DIGU with FT8/FT4. The panel's own `proto_changed` (FT8↔FT4) mirrors into `decode_mode` so the two stay consistent. Deep FT8 signal viewing is provided by the dedicated FT8 band waterfall beside the main waterfall (see `ft8_waterfall.c`), not by force-zooming the main panadapter (that auto-zoom was removed). The app-wide zoom cap was raised from 8× to 32× (`actions.c`, `midi3.c`; the `vfo.c` zoom menu adds quick x10/x12/x16/x32 jumps; `rx_panadapter.c` gridline divisors handle >8× via the `default` case). **Hard limit:** WDSP's analyzer keeps fixed `dMAX_PIXELS` (16384) internal buffers, and `rx->pixels == panadapter_width × zoom` is passed straight to `SetAnalyzer`; exceeding 16384 overruns those buffers and corrupts the heap (blank waterfall **and** broken RX/decode). So `receiver_change_zoom` **and** the panadapter `resize_timeout` clamp the zoom to `16384 / panadapter_width` — the effective max zoom is therefore width-dependent (deeper when the panadapter is narrow, e.g. with the FT8 panel open). A requested 32× is honoured only up to that ceiling; going deeper would need a span-based (`SetAnalyzer` fmin/fmax) rework rather than the pixels = width×zoom model. Callsign/grid are **no longer in the panel** — they live in Configure → FT8 (`ft8_dialog.c`); the panel's config row keeps the operational TX offset/slot plus a **directed-CQ** combo (`cq_dir_changed` → `RADIO.ft8_cq_dir`; blank/DX/EU/NA/… or 3 digits — see `msg_cq`) and a leftmost **FT8/FT4 protocol selector** (`proto_changed` → `RADIO.ft8_proto`; the single source of truth read by the decoder/encoder/QSO/reporters). The band-activity rows also carry a two-level **new-DXCC** highlight (gold = new entity ever, blue = new on the current band) and a country hover tooltip (see `ft8_dxcc.c`). While the panel is open the bottom-bar block switches to a **QSO status** readout (DX call, next Tx message, exchange state, offset/slot) rather than duplicating the list. Panel layout: config row on top, then a horizontal split with the Tx1–Tx6 message column on the **left** and the rolling band-activity list on the **right** (CQ rows green, to-me rows bold, "CQ only" filter via a `GtkTreeModelFilter`; double-click a row to work that station). **List vs. bottom-block semantics:** the panel's band-activity list is an **accumulating history** (append-only, capped at `MAX_ROWS`, never auto-cleared) — distinct from the compact bottom-bar readout, which shows only the latest one-shot decode. The compact bottom-bar decode readout (built in `rds_update_cb`, `radio.c`) is rendered as **Pango markup** (`gtk_label_set_markup`) so **"new one" callsigns are coloured by the same two-level DXCC principle as the big panel** — **gold** (`#b8860b`) for a brand-new entity (any band, `ft8_qso_new_dxcc`), **blue** (`#2f6fb0`) for one new on the current band (`ft8_qso_new_dxcc_band`, band from the active RX dial) — but via **font colour** (per-line `<span foreground>`) instead of the panel's cell background. Message text is `g_markup_escape_text`-escaped; the big panel is unaffected. `refresh()` appends a slot's decodes once, keyed on the slot label `disp_utc` changing. **Erase** (`erase_clicked`) clears the list *and* re-stamps `disp_utc` with the decoder's current batch label — otherwise the decoder's retained last batch (it keeps the last non-empty decodes so the bottom block doesn't blank between slots) would be seen as "new" and immediately re-appended, so the list stays clean until a genuinely new slot decodes. **Enable Tx** / **Auto Seq** toggles, free-text entry, DX + status readout along the bottom. TX offset is also settable by **Shift+click** on the RX panadapter (`receiver_button_press_event_cb`), which draws a green "TX" marker (`rx_panadapter.c`).
- **`sstv_decoder.c/h`** — **SSTV image receive decoder** (Martin / Scottie / Robot / PD). Self-contained analogue-SSTV decoder with **no external DSP dependency** (no WDSP/FFT). Tapped in `receiver.c:process_rx_buffer` on the active RX's 48 kHz demod audio whenever it is in **DIGU/DIGL** (HF SSTV over SSB) **or FMN** (VHF/ISS SSTV over narrowband FM — the ISS transmits on 145.800 MHz FM, so Robot 36/PD120 need the RX in FMN; the audio-subcarrier discriminator is amplitude-independent so FM de-emphasis doesn't hurt it) *and* `radio->decode_mode==DECODE_SSTV`. `decoder_taps_audio()` and the bottom-bar selector/`Show SSTV`/panel gating all special-case FMN for SSTV (FT8/FT4 stay SSB-only) (the shared decoder-tap machinery — unity WDSP panel gain so the tap always sees full level, plus software listen-volume — is now compiled under `#ifdef DECODERS` = `defined(FT8) || defined(SSTV)`, not just FT8). Pipeline: a **51-tap windowed Hilbert-FIR FM discriminator** turns the audio into instantaneous frequency (1500 Hz = black .. 2300 Hz = white, 1200 Hz = sync) written into an absolute-indexed inst-freq ring; a **VIS-header detector** (1900 Hz leader → 1200 Hz start bit → 8×30 ms bits, even-parity checked) auto-selects the mode; then a family-dispatched **per-line decoder** reconstructs the image. **Modes** (`MODES[]`, N7CXI timings), five **families**: **Martin M1/M2** + **Scottie S1/S2/DX** (`FAM_MARTIN`/`FAM_SCOTTIE`, direct **GBR**), **Robot 36** (`FAM_ROBOT36`, YUV 4:2:0 — Y each line + **alternating** R-Y/B-Y whose Y/chroma separator tone encodes which, paired across two rows), **Robot 72** (`FAM_ROBOT72`, YUV 4:2:2 — Y+R-Y+B-Y every line), and **PD50/90/120/160/180/240** (`FAM_PD`, YUV 4:2:0 — **two image rows per transmitted line**: Y0, R-Y, B-Y, Y1). YUV→RGB is full-range BT.601 (`put_yuv_row`). Geometry is per-mode (`img_w`/`img_h`, up to 640×496 for PD120/180/240); the RGB buffer is `MAX_W*MAX_H*3`. **This covers ISS SSTV: Robot 36 (MAI-75) and PD120 (ARISS).** GBR sync placement differs by family — **Martin** sync at line start (offsets positive), **Scottie** sync between blue and red (green/blue read from *before* the located sync, red *after*). **Per-line sync locking** (`locate_sync`, ±12 ms min-|f−1200| search) re-anchors every line to cancel clock offset/slant; **line 0 is anchored on VIS-derived timing, not searched** — the first sync abuts the 1200 Hz VIS stop bit (Martin/Robot/PD) so a search would lock onto the stop bit. A separate **`tx_line`** counter (distinct from the image-row `cur_line`) drives the sync prediction/re-lock, because PD emits two rows per transmitted line. **VIS robustness (from real-signal debugging):** the 1900 Hz leader is **latched** (`leader_deadline`) once ≥180 ms is seen — a raw consecutive-run counter is reset by the finite-slope glide between the 1900 Hz leader and the 1200 Hz start bit on real signals (synthetic tones switch instantly, so this only bit off-air), and both `vis_pending` and `cand_start` are frozen while a header buffers its bits so image content can't re-latch and clobber the pending decode. **Forced-mode sync anchor:** when the operator forces a mode (`sstv_decoder_set_mode(vis)`, panel combo) the decoder **skips the VIS entirely** and anchors line 0 on the first clean sync pulse (a run of ~0.7·`sync_ms` at 1200 Hz) — this is the reliable path for **FM/VHF SSTV (ISS)**, where WDSP's FMN de-emphasis smears the fast 30 ms VIS bits into an unreadable header even though the image itself (slower transitions) decodes cleanly. **Verified on a real ISS PD120 recording** (ARISS Sputnik commemorative image decoded correctly from off-air FM audio). The image lives in a mutex-protected RGB byte buffer; `sstv_decoder_get_image()` (GTK thread) returns a fresh `img_w×img_h` `GdkPixbuf` copy. `sstv_decoder_set_mode(vis)` forces a mode (0 = auto); `sstv_decoder_adjust_slant(dppm)` trims the pixel clock. All decode runs inline on the RX audio thread (atomic no-op when disabled). Compiled only with the `SSTV` flag. Verified end-to-end with a synthetic colour-bar generator (Martin M1, Scottie S1, Robot 36, Robot 72, PD120 → **8/8 bars pixel-correct each**).
- **`sstv_panel.c/h`** — Embedded **SSTV image panel**. A GtkWidget slotted into the RX stack *in place of the second receiver* (mirroring `ft8_panel.c`): shows the incoming image (a `GtkDrawingArea` scaling the decoder's pixbuf to fit, nearest-neighbour, letterboxed 4:3), a status/progress line, a **Mode** override combo (Auto + all modes, `MODE_ENTRIES[]` → `sstv_decoder_set_mode`), **Slant ±** trim, and **Save** (PNG to `~/.local/share/machpsdr/sstv/sstv_<UTC>.png`) / **Clear** buttons. Own ~5 fps `g_timeout` polling the decoder, torn down on `destroy`. Opened via the bottom-bar **"Show SSTV"** toggle (`radio.c:sstv_expand_cb` → `radio->sstv_panel_open`), shown in DIGU/DIGL with the SSTV decoder selected. `radio_sstv_panel_sync()` (`radio.c`, hooked from `receiver_mode_changed` and `decode_sel_changed`) creates/tears down the panel from `sstv_panel_open && mode∈{DIGU,DIGL} && decode_mode==DECODE_SSTV`, disables "Add Receiver" while it owns the slot (it and the FT8 panel are mutually exclusive), and force-closes it on leaving the digital modes or switching decoder. `radio_rebuild_rx_stack` includes `r->sstv_panel` as a stack entry just like `r->ft8_panel`.
- **`subrx.c`** — Sub-receiver support
- **`recorder.c/h`** — **I/Q + demodulated-audio recorder.** A global singleton (own `GMutex`) that, when armed for a receiver, streams two 16-bit stereo WAVs into `~/.local/share/machpsdr/`: `rec_<UTC>_iq.wav` (off-air I/Q at `rx->sample_rate`, tapped in `receiver.c:full_rx_buffer`/`full_diviqrx_buffer` **before** the noise blanker mutates the buffer — so it is genuine off-air I/Q, and in the same 16-bit stereo format the `--faker` replay path reads, hence loop-back-able) and `rec_<UTC>_af.wav` (clean demodulated audio at 48 kHz, tapped at the end of `process_rx_buffer` **before** the software listen-volume). Minimal streaming RIFF/WAVE writer: 44-byte header written up front with placeholder sizes, patched with the real byte counts on stop. Taps (`recorder_iq`/`recorder_audio`) run on the RX audio thread and fast-reject any buffer not belonging to the recording receiver; `recorder_toggle` (GTK thread) starts/stops. Exposed as a **Record/Stop** toggle button in the bottom-bar **SETUP** module (`radio.c:record_cb`), recording the active receiver. Samples are clamped to ±1.0 before the 16-bit conversion. **Settings** live in a **Configure → Recording** page (`create_recording_dialog` in `recorder.c`): output **folder** (blank = default; a "Browse…" folder chooser) and two check boxes selecting **which streams** to write (`radio->rec_iq`, `radio->rec_af`; `radio->rec_dir`) — all persisted in `radio_save_state`. Settings are read when a recording starts (changing them mid-recording only affects the next one); if neither stream is enabled the Record button no-ops with a console note. A stream whose box is unchecked leaves its `FILE*` NULL so its tap writes nothing.
- **`ext.c`** — Thread-safe UI dispatch helpers (`ext_*` functions wrap `g_idle_add()` calls)
- **`log.c/h`** — **Levelled console logging.** Three levels `ERROR < INFO < DEBUG`; macros `log_error()`/`log_info()`/`log_debug()` all write to **stderr**, line-serialised by a mutex (safe from the audio/protocol/decoder threads) and prefixed with the level (`[INFO] …`). The level guard lives in the macro (a single int compare against `machpsdr_log_level`), so a `log_debug()` on a hot path costs nothing — and its args are never evaluated — when DEBUG is off. Threshold defaults to **INFO** and is set at start-up in `main.c` from `MACHPSDR_LOG=error|info|debug` (env) then overridden by the CLI (`--log-level <lvl>` / `--log-level=<lvl>`, `--debug`/`-v`/`--verbose`, `--quiet`/`-q`); `log_set_level_name()` parses the names. **All former `g_print`/`fprintf(stderr,…)`/`printf` calls across the app were migrated to these macros** (errors→`log_error`, status/chatter→`log_info`, hot-path & per-slot traces→`log_debug`); the vendored `ft8_lib/` and `wdsp/` trees were left untouched. New code should use the `log_*` macros, not bare `printf`/`g_print`.

### UI Dialogs
All dialogs follow the `*_dialog.c/h` naming convention: `radio_dialog`, `receiver_dialog`, `transmitter_dialog`, `midi_dialog`, `configure_dialog`, `bookmark_dialog`, `diversity_dialog`, `pa_dialog`, `eer_dialog`, `puresignal_dialog`, etc.

### Threading
Background tasks (protocol I/O, wisdom file creation) use `GThread`. UI updates must be dispatched to the GTK main thread via `g_idle_add()` or the `ext_*` wrappers in `ext.c` — never call GTK functions directly from protocol/audio threads.
